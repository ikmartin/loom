# loom command reference

Generated by `scripts/gen_cli_reference.py` from the command tree; do not edit. Every command has one name, listed in the sections of `loom --help`; a group that runs on its own is documented as a command, then with its subcommands.

# `loom`

`loom [OPTIONS] COMMAND [ARGS]...`

loom: a tool for atomized mathematical development.

Every command except `init` and `doctor` runs against the nearest quilt, found by walking up from the current directory to a `config.toml` with a [quilt] table; `doctor` checks that quilt too when there is one.

| option | description |
|---|---|
| `--version`, `-V` | Show the version and exit. |

## Start

Make a quilt, bring a paper into it, and check what loom needs.

### `loom init`

`loom init [OPTIONS] [DIRECTORY]`

Create a quilt in DIRECTORY (default: the current directory); with --from FILE, import a paper into it: the paper as received kept as the first landmark, and the working document drafted from it.

| option | description |
|---|---|
| `--from` `FILE` | Import an existing paper: FILE is its main .tex file, anywhere on disk. |
| `--demo` | Write the demo quilt instead of a minimal master. |
| `--prefix` | Id prefix for new nodes. |
| `--git` | Also run git init. A quilt is files; loom reads no history. |
| `--ai` | Which AI you use, instead of being asked: any but none gets the agent layer, as loom ai init writes it. |
| `--fix-anchoring` | With --from: rewrite the drafted document so every theorem-like \begin and \end is alone on its line. |
| `--yes`, `-y` | Skip questions; take defaults and confirm the import. |
| `--dry-run` | Say what would be created, and write nothing; no identity test. |
| `--json` | Print the report as one JSON object. |

### `loom import`

`loom import [OPTIONS] FILE`

Bring a paper into the quilt: the paper as received kept as a landmark, and the working document drafted from it at once, with its styles, bibliography and figures beside it in a directory of its own.

| option | description |
|---|---|
| `--yes`, `-y` | Import without asking for confirmation. |
| `--no-check` | Skip the identity test. |
| `--fix-anchoring` | Rewrite the drafted document so every theorem-like \begin and \end is alone on its line. |
| `--to` `FILE` | The working document to draft, a .tex anywhere the scan reads (default: STEM/FILE, the paper's file in a directory of its own). |
| `--dry-run` | Say what the import would write, and write nothing; no identity test. |
| `--json` | Print the report as one JSON object. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom atomize`

`loom atomize [OPTIONS] [SRC]`

Write the spine --to FILE, a copy of SRC with an inclusion line in place of each node, and each node into nodes/<id>.tex.

SRC is not modified; the history records that the spine superseded it, so it defines nothing until `loom live`.

| option | description |
|---|---|
| `--to` `FILE` | The spine to write: SRC with inclusion lines in place of its nodes. |
| `--key` `KEY` | Move only these nodes, wherever they live; SRC is not needed. Writes the node files and prints the patch for the source, which loom never edits. |
| `--proofs` | Keep each proof in its statement's node file, or give it a file of its own. |
| `--sections` | Also move labelled sections and subsections to nodes/. |
| `--all` | Act on SRC and every file it reaches, writing spines under --to-dir. |
| `--to-dir` `DIR` | With --all: the directory the spines are written under. |
| `--retire` | Move SRC into .loom/records/retired/ once its spine is written, instead of leaving it superseded in place. |
| `--dry-run` | Say what would be written and moved, and write nothing; no identity test. |
| `--json` | Print the report as one JSON object. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom doctor`

`loom doctor [OPTIONS]`

Check the TeX toolchain and what loom needs of it, poppler, git, the author name and the viewer bundle; inside a quilt, also its engine, its generated files, its .gitignore and its config.

Each item is ok, warn (works, but you will hit it) or fail (a command you need will refuse), with the command that fixes it. Exits 0 when nothing fails and 2 when anything does; under --strict a warning counts as a failure. Without --repair it writes nothing; a tool is run only to ask its version or test what loom needs of it, and one that has not answered in 10 s is reported as hung.

| option | description |
|---|---|
| `--json` | Machine-readable report on stdout. |
| `--strict` | Count a warning as a failure: exit 2 when any item warns. |
| `--repair` | Repair TeX first: install loom's own TeX, or put back what it lacks. Touches nothing outside loom's directory. |
| `--settle` `ID` | Settle a write loom could neither finish nor undo as it stands, by the id the writes item gives: your files stay as they are, each suggested edit it wrote is recorded as the files show, and it is no longer said. The author's; refused in an agent's shell. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom lint`

`loom lint [OPTIONS]`

Scan and print every diagnostic, each with its class.

A class says what kind of problem it is: latex, a problem in a document's LaTeX, a last compile that failed among them, and all the viewer shows a person; model, loom's model of the quilt (ids, \uses, links, copies, records), an agent's to keep; internal, loom's own difficulty or the integrity of its records. An error is a fault in what TeX compiles, or in loom's records; exit 1 on one. Fast: no LaTeX runs, and a compile's problem is read from the log the document's last compile left.

| option | description |
|---|---|
| `--json` | Print the report as one JSON object. |
| `--nodes` | One block per node id: what is wrong with its identity, and the superseded files. |
| `--session` `SESSION` | Log this call to the session. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom status`

`loom status [OPTIONS]`

List every key with its computed state, cause if stale, and review facts; it exits 0 whatever it finds, and 2 only on an argument it refuses.

Annotations on works are not on keys and appear in no row; `--reading` lists them by work, and `--json` always carries them under `reading`. While `loom serve` runs, a document it last compiled with errors or into no PDF is listed too, and `--json` carries how each of its compiles stands under `compiles`.

| option | description |
|---|---|
| `--stale` | Accepted keys whose text, closure or preamble moved since. |
| `--draft` | Keys never accepted. |
| `--incomplete` | Keys marked \incomplete. |
| `--loose` | Keys no live document reaches. |
| `--retired` | Keys accepted once and defined by no document now. |
| `--master` `DOC` | Keys this document reaches. |
| `--in-order` | With --master: the document's keys in the order it prints them, sections and an agent document's own among them, each with its state. |
| `--tag` | Keys carrying this tag. |
| `--type` `TYPE` | Keys carrying an annotation of this type, by id or name. |
| `--status` | Keys carrying an annotation in this state. |
| `--detached` | Keys whose annotations no longer find their quoted text. |
| `--reading` | List the annotations on works, by work; they are in no row and count toward nothing otherwise. |
| `--explain` `KEY` | Why KEY is in its state, with the diff of what moved. |
| `--json` | Print the report as one JSON object. |
| `--session` | Log this call to the session. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom source`

`loom source [OPTIONS] TARGET`

Print TARGET's LaTeX source: a key's own text, or a document flattened with every inclusion expanded in place.

This is how a reader or an agent gets the text of a result or of a whole paper. It writes nothing: there is no file to clean up, none to keep out of version control, and none to go stale against the author's next edit. A section's key prints the section with everything in it.

With --closure, a key is preceded by exactly the statements it depends on, in dependency order. A document is already whole, so --closure does not apply to one. With --at REF, the key's text as it stood then: the text an annotation was written against, the text last accepted, or a step of the history; --diff shows what has changed since.

| option | description |
|---|---|
| `--closure` | Everything TARGET depends on, in dependency order, then TARGET itself. |
| `--at` `REF` | The key's text at REF instead: an annotation's id, `accepted` (or `accepted:NAME`), or a step of the history. |
| `--diff` | With --at: a unified diff from that text to the key's text now. |
| `--session` `SESSION` | Log this call to the session. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom link`

`loom link [OPTIONS] THING`

Print a markdown link to THING that the viewer can follow.

THING is a node or any key in it, a document's path, an annotation id, a session id, a work (its reference, or the key its entry has), or a file the viewer shows by its path (`notes/day1.md`, `--at` a heading's id; a PDF `--at page=N`; a text file `--at L12`). `--quote` carries words in a document, a project PDF or a work, which the viewer opens at and lights. The link's text is empty: the viewer names the thing itself, as `Theorem 3.1`, and keeps the name right when the document is renumbered; write your own words between the brackets to show those instead. A thing the viewer does not show is refused, with why.

| option | description |
|---|---|
| `--at` | A place in THING: a key inside the document or node, a heading's id in a Markdown file or notebook, page=N in a PDF, L and a line number in a text file. |
| `--page` | A page of a work's PDF, from 1. |
| `--quote` | Words to open at and light: on the work's page, on the PDF's page given by --at page=N, or at the place in a document; anywhere in it with no page or place. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

## Review

Annotate, accept, keep or undo what changed, see what rests on what, what is known of a result, and Lean's check of it.

### `loom annotate`

`loom annotate [OPTIONS] [TARGET] [MESSAGE]`

Write an annotation on TARGET: a key, an equation's qualified key, a master path, a work, or a project PDF; a MESSAGE of `-` is read from stdin.

An annotation carries its author, its time and the version of the text it was written on, and belongs to no session. A work is named by its reference, or by the key its entry has; one on a work with no --page is on the whole work. One on a page of a PDF -- a work's, or a project PDF by its path -- names the page with --page and the place with --quote (words on it), --box (a rectangle) or --stroke (ink), drawn with a --mark tool where it is not on words; `loom status --reading` lists those on cited works.

| option | description |
|---|---|
| `--quote` | Anchor to this exact text: once in a key's own text, or on the page of a cited work given by --page. |
| `--page` `N` | Page N of a PDF: a work's (TARGET its reference, or the key its entry has) or a project PDF by its path; with --quote, --box or --stroke. |
| `--box` `X0,Y0,X1,Y1` | Anchor to a rectangle on the page, in points with the origin at the top left; ';' separates several. With --edit, where a drawn one stands now. |
| `--stroke` `X,Y,X,Y,…` | A line of ink or an arrow on the page, in points from its top left; repeat for more lines. With --edit, its lines now. |
| `--mark` | Draw it on the PDF page with this tool: a pin or words on the page in the --box, a box or an oval round it, ink or an arrow along each --stroke. |
| `--type` `TYPE` | The annotation's type, by id or name, from the quilt's annotation types; default none. With --edit, '' takes it off. |
| `--color` | Its colour, over its type's. |
| `--style` | How it is drawn on words, over its type's. |
| `--weight` | An underline's or a strike's thickness, in whole pixels. |
| `--opacity` | Its opacity, in percent. |
| `--as` `NAME` | Who is writing; an agent's name ends in Agent. |
| `--reply` `ID` | Answer annotation ID; the message is the reply. |
| `--resolve` `ID` | Mark annotation ID resolved, with the message as why. |
| `--edit` `ID` | Restate an annotation: a new body, --type, a look, or where a drawn one stands; never its anchor. |
| `--delete` `ID` | Delete an annotation, with its replies; an agent deletes only its own. It is removed from the log, not marked. |
| `--in` `DOC` | A claim about the node as read in this document: marked there, listed on the node's own page, absent elsewhere. |
| `--undo` | With --resolve, open the annotation again: an undo is another event, never a removal. |
| `--batch` | Read JSON lines from stdin, one annotation or one change per line; an unknown key is an error. |
| `--dry-run` | Say what would be written, and write nothing. |
| `--json` | Print the report as one JSON object. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom suggest`

`loom suggest [OPTIONS] [KEY]`

File a suggested edit on KEY: --with NEW in place of --quote OLD, or beside it with --before or --after; without --quote, of the key's body.

The person keeps or discards it with `loom changes`: keeping writes it into the file, discarding leaves the text as it is, and `loom changes ID` prints the patch that takes it. An edit that names the annotation it --answers resolves that annotation when it is kept. `--before` with no quote puts the text at the head of the body, which is how a `\uses{…}` is proposed. `--withdraw EDIT` takes back one of your own while it is open; `loom changes --by NAME` lists the edits NAME suggested, in every state.

| option | description |
|---|---|
| `--with` `NEW` | The new text; '' deletes the quoted words, and - reads it from stdin. |
| `--quote` `OLD` | The words it replaces, once in the key's own text and inside the block, short of its \begin and \end; without it, the key's body. |
| `--before` | Put the new text right before the quoted words, or at the head of the body. |
| `--after` | Put the new text right after the quoted words, or at the end of the body. |
| `--answers` `ID` | The annotation it answers; keeping the edit resolves it. |
| `--comment` `TEXT` | What to say beside it, in Markdown. |
| `--as` `NAME` | Who suggests it; an agent's name ends in Agent. |
| `--withdraw` `EDIT` | Withdraw suggested edit EDIT, one of yours still open, instead. |
| `--why` | With --withdraw, why. |
| `--dry-run` | Say what would be filed, and write nothing. |
| `--json` | Print the report as one JSON object. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom changes`

`loom changes [OPTIONS] [ID]`

List what waits on you, by document: each open suggested edit and each in-place edit since your last look to an open file agents may edit, cut by words; with ID, print the change's patch, which `git apply` takes as it stands.

The open files are the ones the viewer shows that are text, at most 1 MB, LaTeX's auxiliary files left out; your look holds the text of each one agents may edit as you last saw it, and `loom serve` takes your first when it starts. A place agents are denied is yours, and an edit there is never listed, whoever made it. Keeping and discarding are yours, never an agent's: keeping an in-place edit puts it into your look, keeping a suggested edit writes it into its file; discarding an in-place edit puts its old words back, discarding a suggested edit leaves the text as it is. A version of each document a write changes is kept first. Keeping says nothing about whether the mathematics is right, which is `loom accept`'s.

| option | description |
|---|---|
| `--document` `DOC` | Only the changes in the files DOC is made of. |
| `--keep` `ID|PATH` | Keep the change ID, or every change in PATH; may repeat. |
| `--discard` `ID|PATH` | Discard the change ID, or every change in PATH; may repeat. |
| `--keep-all` | Keep every change; with no look of yours yet, take it first. |
| `--discard-all` | Discard every change. |
| `--why` | With a discard, why, which the agent that suggested an edit reads. |
| `--by` `NAME` | NAME's suggested edits, in every state. |
| `--json` | Print the report as one JSON object. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom formal`

`loom formal [OPTIONS]`

`loom formal [OPTIONS] [COMMAND] [ARGS]...`

Run alone, `loom formal` is a command; its subcommands follow its options.

Say whether formalization is on for this quilt on this machine, and whether loom can check its Lean here.

The person turns it on (`loom formal on`), which installs Lean, its toolchain and Mathlib and makes the quilt's Lean project; from then an agent writes Lean in the project, marks each declaration that states a result with `@[loom "LABEL"]`, and asks loom to check it (`loom formal check`). What Lean said is loom's own record, never an agent's.

| option | description |
|---|---|
| `--json` | Print the report as one JSON object. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

#### `loom formal check`

`loom formal check [OPTIONS]`

Have loom check the quilt's Lean itself: rebuild the project from clean, read which declaration states which result (`@[loom "LABEL"]`) and the axioms each rests on, and replay the build in Lean's kernel, every step fenced, with no network and writes only in the project. Each result a declaration states gets loom's own record of what Lean said, which stops standing once its Lean or its statement changes.

Refused when formalization is off here, and from a shell that is itself fenced, such as an agent's sandbox, where the fence cannot be put up: ask through loom's tools instead.

| option | description |
|---|---|
| `--json` | Print the report as one JSON object. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom mv`

## Publish

Build the site and the PDFs, serve them and the home page, and open the viewer at a link.

### `loom build`

`loom build [OPTIONS]`

Scan, derive, render, and publish .loom/cache/site/, what the viewer is served. Exit 1 if any error-severity diagnostic exists outside the works nothing cites (the build is still published).

A whole build then removes what loom keeps for no purpose any more: from .loom/cache/ what this build does not name and nothing has written in the last hour, an agent's scratch fourteen days after its session last wrote, and a saved preview fourteen days after it was written; a build of --keys removes nothing.

A document is read from the HTML its compile made, and shows as its source until one has. Text no compile makes, a node no document reaches, a landmark, a comparison, is made by TeX as snippets. Rendering is cached per block by its inputs, which include loom's own version and, in a checkout, loom's code; --force renders everything regardless, and makes again every text TeX refused before. Only errors are listed; `loom lint` lists every diagnostic.

| option | description |
|---|---|
| `--keys` | Limit rendering to these keys and their masters; the manifest is always complete. |
| `--force` | Render every block again, ignoring the cache and making again every text TeX refused. |
| `--no-compile` | Run no TeX: text no compile makes comes from the cache, else shows as its source. |
| `--json` | Print the report as one JSON object. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

### `loom serve`

`loom serve [OPTIONS]`

Serve the viewer for this quilt and keep it current: it republishes on every change until interrupted.

The viewer is at /, and what it reads at /build/. One server runs per quilt. At rest after a build, at most once an hour, it removes what loom keeps for no purpose any more, as a whole loom build does: from .loom/cache/ what its last build does not name and nothing has written in the last hour, expired scratch and old saved previews. Every document a change reaches compiles in the background, the one being read first, as does on starting each one never compiled or edited since; a compile that makes no PDF leaves the last good one, and `loom status` lists it.

A quilt an earlier loom made is served waiting: the viewer offers to bring it forward, as loom upgrade does, and nothing is built until it has.

| option | description |
|---|---|
| `--port` | Port to listen on; fails if busy. Default: the one this quilt keeps on loom's home, else 8791. |
| `--open` | Open the browser. |
| `--no-compile` | Run no TeX: compile nothing, neither after a change nor on starting, and make no snippets. |
| `--viewer` `PATH` | Serve the built viewer at PATH from where it lies, read on every request, so a rebuild of it shows on a reload: for trying a change to the viewer. |
| `--quilt` `PATH` | Quilt root (default: discovered by walking up). |

| option | description |

| `--install` | Write loom's app in ~/Applications, which opens the home page, say where, and return. |
| `--no-compile` | Serve every quilt with no compiles, as loom serve --no-compile. |

### `loom compile`

`loom compile [OPTIONS] [TARGET]`

Run latexmk from a master's own directory into its compile folder, .loom/cache/tex/<stem>-<hash>/ (default: the default master), or for a key.

Compiling a key builds the document of its closure and runs latexmk on that, so `--with` previews a proposed diff and `--draft` a node that has no id yet: neither writes into the quilt. `--html` also makes a document's HTML as TeX makes it, which its fragments are cut from: the page, the fragment loom rebuilt from it, and how many of the document's nodes and blocks it places.
