# Release checklist

Applied to every tagged release of loom (`docs/contributing.md`). A release is a GitHub release of `ikmartin/loom` holding the wheel `loomtex-X.Y.Z-py3-none-any.whl`, with the viewer built and vendored into it, `install.sh`, and `loom-release.txt`, which names the wheel and its checksum for the install line; `.github/workflows/release.yml` makes it as a draft. Nothing is published to a package index. Tagging, running the release workflow and publishing are the maintainer's own steps, never a script's or an agent's.

1. The commit to be tagged is on `main` and its CI is green (the `loom`, `viewer` and `docs` workflows, which run `scripts/verify`; the `loom` workflow's TeX tier compares the conformance fixture with a fresh build). Locally, `scripts/verify full` and, with the arXiv sources, `LOOM_PAPER_FIXTURES=... scripts/verify paper`.
2. `loom check` passes on the demo (`loom init <scratch>/demo --demo`), on `demos/synthetic`, and on the paper quilts `demos/man12` and `demos/acgs`, which `python demos/build.py` builds from the gitignored sources under `tests/fixtures/`.
3. The Overleaf manual test on the demo quilt: zip its `drafting/`, the main document's own directory, which holds everything the document reads; upload; set `main.tex` as the main document; compile; compare with the local PDF; record Overleaf's TeX Live version and the result in the release notes.
4. Loom's TeX and tools archives, the first time and again when the TeX Live year or a tool's version changes: run `release.yml` by hand with `tex` and `tools` checked; attach the archives it uploads (`loom-tex-darwin.tar.xz`, `loom-tools-darwin-arm64.tar.xz`, `loom-tools-darwin-x86_64.tar.xz`) to a published GitHub release, since a draft's files cannot be downloaded without signing in; and put each URL and its `.sha256` in `ARCHIVE["darwin"]`, `TOOLS_ARCHIVE["darwin-arm64"]` and `TOOLS_ARCHIVE["darwin-x86_64"]` in `loom/src/loom/tex/private.py`, committed before the tag. While those are empty the install line builds loom's TeX from TinyTeX and installs no Ghostscript or poppler.
5. Versions: bump `version` in `loom/pyproject.toml` and `__version__` in `loom/src/loom/version.py` together (semantic versioning, independent of the viewer's). A unit test holds the two equal, and the release workflow refuses a tag that is not both.
6. A dry run: `release.yml` run by hand on that commit, with neither box checked, builds everything a tag would and uploads it as the artifact `release`, making no release.
7. Tag `vX.Y.Z` and push the tag. `release.yml` builds the viewer from the tagged commit, vendors it (refusing a viewer with uncommitted changes or a bundle stamped `-dirty`), builds the wheel, installs it with uv's Python 3.13 and checks that it runs, carries that bundle and has the tag's version, then makes a draft release with the wheel, `install.sh` and `loom-release.txt`. The bundle committed under `loom/src/loom/assets/viewer/` is not what ships; the one the workflow vendors is.
8. Read the draft and publish it, not as a pre-release: the install line reads `releases/latest`, which is the newest published release that is not a pre-release.
9. On a clean Mac, the install line in `README.md` as written; then `loom doctor`, whose `viewer bundle` row names the tagged commit, and `loom serve` on a quilt.
