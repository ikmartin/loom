# Write API

The write API is the HTTP form of the publisher's local commands, so that a browser can request record writes and the person's own acts on their files. It is served by the publisher (loom's `serve`), never by the viewer.

**[decided]** The commands it wraps are library functions with the same signatures, and a viewer detects it rather than assuming it.

## 1. Discovery

**[decided]** `GET /_api` returns `{"write_api": 1, "capabilities": [...], "format": {"found": N, "reads": N}, "token": "...", "quilt": "9f2c…", "pid": 4242, "stream": true, "connected": [...], "frames": "http://127.0.0.1:PORT", "viewer": "1794507956349", "stale": false, "home": "http://127.0.0.1:8790/"}` or 404, and 403 to a request a browser says came from another page (§3). `frames` is the frames origin an HTML file is shown from (§3), absent where none runs. `pid` is the server's own process, at which the home stops a server it found running (§7), since the `serve.json` in a quilt travels with a copy of it. `home` is the address of loom's home page (§7) while a home runs on this machine, absent otherwise, so a page whose server has stopped can send the person there. `viewer` is the version of the viewer the publisher serves (its `_app/version.json`): `loom serve` keeps the Python it started with, so it serves the machine's copy of the viewer version it started with rather than the vendored bundle, and a viewer vendored while it runs is not served beside code it was not built for. `stale` is true once the vendored viewer or loom's own code has changed since the publisher started. A viewer that finds `stale` says to restart `loom serve`; one whose own version is not `viewer` says to reload, and asks again whenever the stream reconnects. `stream` says `GET /_api/stream` is served: a `text/event-stream` with an event `manifest`, carrying nothing, each time a new manifest is published; an event `compiles` on opening and each time a compile starts, ends or is asked for, carrying one JSON object keyed by document path, each `{"state": "queued"|"compiling"|"idle", "again": bool, "last": null | {"result": "ok"|"errors"|"failed", "ended", "error", "at"}}`, where `errors` made a PDF though LaTeX reported errors, `failed` made none so the last good one stays, and `at` is the log's `l.N` line where TeX stopped; an event `connected` on opening and each time the list of connected agents changes, carrying that list as `connected` below; an event `library`, carrying `{"gen": N}`, each time the library's generation moves (§6, "The library's generation"); and a comment every fifteen seconds while idle. The token is what every write must carry (§3). `quilt` names the quilt the publisher serves, by a digest of where it lies and never the place itself, so a viewer can keep what it remembers per quilt: a folder copy served later on the same port is another quilt. A viewer that receives 404 or a version it does not accept shows no editing affordances. The capability list is what this publisher actually serves, so a viewer must read it rather than assume the table below: an endpoint absent from the list answers 404, and a viewer that hides the affordance is correct.

**[decided]** **A quilt an earlier loom made.** `format` says which layout the publisher found the quilt in, `found`, and which this loom reads, `reads`: the numbers `.loom/format` holds, equal once the quilt is in this loom's layout. `loom serve` on a quilt in an earlier layout this loom can bring forward starts waiting: it builds, compiles and watches nothing, runs no frames origin, and serves only the viewer's own files, `GET /_api` (with `found` below `reads`, `capabilities` holding `library-upgrade` alone, and no `frames`), `GET /_api/stream`, and the one write `POST /_api/library-upgrade` (§2), with the token and the checks of §3 as any write. Every other request, `/build/` and every other `/_api/` address included, answers 409 `format-old`. Once `library-upgrade` has answered, the publisher serves every request and starts as it does on any quilt: its first build, compiles and watchers follow the answer, and with them the stream's events.

**[decided]** **Who is connected.** Each `loom mcp` process, the server an agent's app starts for one conversation, keeps a record of itself at `.loom/local/live/<pid>.json`, and `connected` is the records of the processes alive as `loom serve` last looked, at most a second ago, the oldest first, served where the stream is; no request waits on the records. A record is written at the server's first request of either kind (`initialize`, or any request of a client that sends none, such as `server/discover`), written again in place at each tool call, prompt or resource read and when a loom session is bound to it, and removed when the server is stopped by SIGINT, SIGTERM or SIGHUP or ends on its own. Each is one JSON object:

```json
{
  "format": 1,
  "pid": 4242,
  "ppid": 4200,
  "as": "Claude Code Agent",
  "client": {"name": "claude-code", "title": "Claude Code", "version": "2.1.312"},
  "protocol": "2026-07-28",
  "conversation": "5b6c0e2a-…",
  "entrypoint": "claude-desktop",
  "session": "s-2026-11-17-ab12",
  "loom": "0.1.0",
  "started": "2026-11-17T14:02:11Z",
  "last": {"kind": "tool", "name": "loom_annotate", "when": "2026-11-17T14:05:40Z"}
}
```

`pid` is the server's and `ppid` the process that started it, the agent's app; `as` the agent's name, under which it writes; `client` the app's own `name`, `title` and `version` as its first request gave them (a request's `_meta` `io.modelcontextprotocol/clientInfo`, or `initialize`'s `clientInfo`), null when it gave none; `protocol` the MCP version that request spoke. `conversation` is the app's id for the conversation (`CLAUDE_CODE_SESSION_ID` in the server's environment) and `entrypoint` how the app was started (`CLAUDE_CODE_ENTRYPOINT`, `claude-desktop` in the desktop app), each null where the app sets none. `session` is the loom session the server writes into, null until it has one (`docs/design/agents.md`). `last` is the latest call, `kind` one of `tool`, `prompt`, `resource` and `name` the tool, prompt or resource, null before the first. Times are the clock's, ISO 8601 UTC. Nothing counts the agents behind one record: an app's subagents share its connection and its name, so one record may stand for several, and a record is a conversation, not a person or a model at work. A viewer says "connected" of a record in the list and "active" of one whose `last.when` is recent; neither says the agent is working.

**[decided]** A record is one machine's: ignored by git, never read by a build, and checked when read, since it travels with a copied quilt and a process id is reused. The server holds an exclusive lock (`flock`) on its record's file for as long as it runs, and no command it runs inherits it. A reader that can take a shared lock on a record without waiting knows no process holds it, whatever its `pid` names now, and deletes it: so a server killed outright, a record copied with a quilt and a `pid` taken by another process all leave the list at the next look, which `loom serve` takes once a second and `loom mcp` takes when it starts. Only a regular file named for a `pid` in ASCII digits is opened, never through a link and never so that it waits (a FIFO), and `.loom/local/live/` only when it is a directory and not a link; anything else there is left alone, and no entry stops the look at the others. A record that does not parse, whose `pid` is not its file's name, or whose lock cannot be tried (a filesystem without locks) is left where it is and not listed. A server writes its own record over anything else standing at its name. A quilt synced live between two machines with an agent on each would see the other's record as unheld and delete it; that is outside what a record is for.

## 2. Endpoints

**[decided]** All requests and responses are JSON. Errors return `{"error": {"code": "...", "message": "...", "fields"?: {...}}}` with 4xx status, `fields` naming the reason for each field of a form it refused; the codes are the CLI's exit reasons. A request that names something that does not exist answers 404 with `no-such-` and what it named (`no-such-node`, `no-such-annotation`, `no-such-session`, `no-such-quote`, …), the same refusals the CLI exits 2 for; 400 is a malformed request or a write refused on its merits, 403 the CSRF gate (`refused`) or an author's act refused to an agent (`author-only`), 409 a conflict with the quilt's state, `format-old` among them: every request a publisher waiting on a quilt an earlier loom made does not serve (§1). An annotation belongs to no session, so no annotation endpoint names one, and a `session` sent with one is ignored. A JSON body over 344 MB, a 256 MB PDF in base64, answers `too-large` (413) before it is read; `library-receive` streams a file of any size (§6).

**[decided]** `GET /_api/events?session=ID&since=SEQ` answers `{session, from, seq, events}`: the events after `SEQ` in the transcript's page form (specs/manifest.md §10.1) and the last sequence number. It reads by an index of where each event starts, so a poll costs what is new; a `session` that is not an id's shape is refused.

**[decided]** `here` is the reader's place, which `loom here` reports to an agent. A tab posts it after a change of the focused item, the block at the top of its pane, the selection, the PDF page, the session or the block under review has settled, and again when it gains focus, so the tab touched last wins. `item` and `beside` are the focused pane's active item and the other pane's, in the viewer's item shape (`{kind, id, place?}`); `block` is `{src, key}`, the `data-src` and key of the block at the pane's top; `selection` is `{key, text}` in a document, `{file, text}` in a project file, or `{page, text?, rects}` on a PDF page, in points from the page's top left, the box tool's region included; a file item's `place` is its heading, `page=N` or anchor; `page` is the PDF page in view; `annotation` is the id of the annotation whose popup is open, which `loom here` names with a crop of its page when it is on one, as it does a region drawn on a page; `review` is `{key, cause}`, the block under review, the cause in the viewer's words: on `/review` in place of the workspace, and in a document beside Review's panel (`?review=`) alongside its item; on any other page, `route` is `elsewhere` and `path` is the viewer's. A place over 64,000 bytes, or with no `route`, is refused with `bad-field`. `GET /_api/here` answers `{place, when, age}`: the last place, the second it came and how many seconds ago, `place` null before any tab has reported. It requires the token and this server's origin, like a write, since where a person is reading and what they selected are theirs. Nothing writes it to disk, and a server's stop forgets it.


**[decided]** `compare` answers `{ok, left, right, pairs}`. `left` and `right` are `{item, kind, macros}`: the item as asked, `"document"`, `"landmark"` or `"node"`, and the manifest macro set its renderings are typeset with (`canon:<stem>` for a landmark, null for the default). Each pair is `{pair, base, left, right}`: the plain key; which side holds the base — `"left"`, `"right"`, `"both"` when the node changed on both sides since the version an agent document began from, or null when nothing orders them; and per side `{key, hash, fragment?}`, the node's key there, its `data-hash`, and a fragment path under the build directory with the changed words marked as Review marks them. A pair whose hashes agree is no difference and is left out, a display name changed alone included. A pair the quilt no longer has a live node for has no `fragment`, and the viewer keeps its whole-node marks. An item that is none of these is refused with `unknown-item`, 404. It is a read: the publisher does not rebuild after it. The answer is computed when asked, never at build, since the pairs two items can form grow with the square of the landmarks.

**[decided]** `session-purge` is **not** an endpoint and will not become one. Purging erases a session's directory and transcript for good, and the one place that should be reachable from is a terminal where the author typed the word.

**[decided]** `annotate` with `page` records an annotation on a page of a work's PDF (DR-209) through the same mapping `locate` previews — one function on the publisher, so what the viewer showed is what the log says. Both read the page text loom derives from the PDF when it is first read (`.loom/cache/library/pages/<hex>/`, by the PDF's hash). `locate` with `span` maps offsets into the page's text, which is what a `span=` locator in a URL carries. `locate` with `text` and no `page` maps the quote on the first page whose text holds it, which is what a `quote=` locator with no `page=` carries; it is refused with `not-found`, 404, when no page does.

**[decided]** `locate` maps a selection to an anchor **on the publisher**, never in the browser. The client's text layer is a third extraction of a page, after loom's page text and the word boxes; only the publisher holds the other two, and only the publisher can say what the page says. The client sends the selected string and never a decision about what the anchor is. Geometry-only anchors are legal and are never refused.

**[decided]** `undo: true` on `resolve` opens the annotation again (DR-174). It appends another event rather than removing one, so the record still says that it was resolved, when and by whom, and that it was reopened. A viewer offers it in place of the verb that fired, which is what lets those two act on a single click: a wrong one is one click back.

**[decided]** A change is kept or discarded where it is drawn, in its document or in Review, never resolved. Its id is what both endpoints take: `c-` and eight hex digits for an in-place edit, its content's hash, which stands while the change does, and a suggested edit's own id. Every write loom makes on the person's word goes into their look too, so a suggested edit kept is not listed back as an in-place edit of its words; a suggested edit whose key already reads as it taken is kept without writing. An agent withdraws its own open edit with `loom suggest --withdraw ID`; keeping and discarding are the author's.

### The Overleaf mirror

A quilt may mirror one Overleaf project, read over git and never written back (`loom/src/loom/overleaf.py`). These are the person's acts, refused to a declared agent (`author-only`, 403). They wait on Overleaf, so the publisher runs them outside the publication's lock. Every refusal loom knows answers with its code and its words, never a 500: reaching Overleaf, `no-git`, `no-token` (no token kept for Overleaf on this machine), `token-refused` (Overleaf refused it; a refused token is forgotten), `no-git-access` (the project's owner has no git access, or the link is not the project's), `offline`, `failed`; the mirror's own, `bad-record` (the record that came with the quilt names something loom does not accept: it holds only the project's id, the folder's name and the main file's, each checked at every read, and loom builds the project's address from the id), `taken-in` (another update took the revision in first), `no-clone`; and the door's (`docs/design/writes.md`). Loom's clone is used only where this machine made it for this quilt and project, and only while nothing in it that can name a program or an address (its configuration, attributes, grafts, alternates) has changed since; any other is made again, never repaired in place.

## 3. Authorship

**[decided]** `author` defaults to the publisher's resolved author name; `as` declares an identity, and an agent names itself including `Agent` or `AI`. The author's verbs refuse a declared agent identity whichever surface it came through, here with 403 `author-only`. A write that names no author is taken for the author's own click in the viewer, which is why no page but the viewer may make one (below).

**[decided]** **Every write carries three checks.** They are CSRF protection and not a login: they keep other *pages* out, not other people.

1. **`X-Loom-Token`** must equal the token the server keeps outside the quilt, in a file only its owner can read in the machine's place (`loom/src/loom/machine.py`), which `GET /_api` serves and the viewer reads.
2. **The page it came from** must be this server's: `Origin`, when present, is this server's own, and `Sec-Fetch-Site`, when present, is `same-origin` (or `none`, the person typing the address).
3. **`Content-Type: application/json`** is required.

A browser blocks a cross-origin *response* and never the *request*, so any page the author happens to be reading could otherwise POST into their quilt and create, resolve or delete. A cross-site form post can set neither a custom header nor a JSON content type, which is what closes it. The socket still binds to loopback, which keeps other machines out; it never kept out the page the author was reading. A request failing any of the three answers 403 with `{"error": {"code": "refused", ...}}`.

**[decided]** **Every request names this server.** `loom serve` answers no request, a read included, whose `Host` is not `127.0.0.1:PORT` or `localhost:PORT` with its own port: it answers 403. A browser sends the name its page was loaded by, so a domain pointed at 127.0.0.1 (DNS rebinding) is same-origin with the server as the browser sees it and passes check 2, and would otherwise be given the token by `GET /_api` and every file under `/_files/`, `/build/`, `/_api/library/pdf/` and `/_api/library/thumb/`, which ask for no token. A viewer reached through a tunnel must keep the server's port.

**[decided]** **No page but the viewer runs in the viewer's origin.** The token keeps other sites out, but `/build/` and the library's documents are served from the viewer's own origin: `/build/` serves what loom derives (`.loom/cache/site/`, and the compile folders of `.loom/cache/tex/` under `/build/tex/`), which an agent running as the person can still write, and `GET /_api/library/pdf/<hex>` and `/_api/library/thumb/<hex>.png` serve a PDF the library stores by its hash (`.loom/library/documents/`) and its first page as an image, which nobody at loom wrote, with no token, since PDF.js and an `<img>` send none, and `Cache-Control: immutable`, since what a hash names never changes. So everything but the viewer's bundle, which is those files and every JSON answer, is served with `Content-Security-Policy: sandbox` and `X-Content-Type-Options: nosniff`. A page there, HTML or SVG, runs no script and has an opaque origin: it cannot read `/_api`, and a POST it made would carry `Origin: null`, which check 2 refuses. `GET /_api` applies check 2 too and answers 403 `refused` when it fails, so the token goes only to the viewer's own origin. The viewer reads these files with `fetch`, `<img>` and PDF.js, which a response's sandbox does not touch, and a PDF opened in a tab of its own is shown by the browser's viewer as before. A project file the viewer shows is served the same way at `/_files/PATH` (manifest §1, `files`), and nothing hidden is.

**[decided]** **A Markdown file's body is drawn in the viewer's own page**, so a publisher writes the HTML it holds through an allowlist first (specs/dialect.md §1), and nothing from it runs as the viewer: not a script, a handler or a `javascript:` address. A frame in it loads only an `https:` address, which is never this origin, since `loom serve` answers on `http:`. The body is confined under `/build/` as every file there is, which does not touch the viewer's read of it, and the viewer's own page carries no policy that would stop the frame.

**Open.** The allowlist is the publisher's, and a viewer inserts what it reads. An agent running as the person can still write `.loom/cache/site/`, though it is no place of the agent's, so a body or a manifest it edits there directly reaches the page unfiltered and can read the token; this was reproduced on 2026-11-04 against a real `loom serve`, and predates HTML in Markdown files. See the [invariant](../design/invariants.md#a-page-the-quilt-holds-never-runs-as-the-viewer).

**[decided]** **An HTML file runs on the frames origin** (plan 0.22.7). `loom serve` answers the project's shown files a second time on a loopback port of their own, which `GET /_api` names as `frames`, so an HTML file the viewer frames runs as a page of its own origin: its scripts run and embedded players (a video) play. That origin serves GET and HEAD for shown files and nothing else — no `/_api`, no bundle, no build output, no store — answers only a request addressed to its own host and port, and sends no CORS headers; check 2 refuses it, so a page there can never read the token or write. **What a page there may rely on:** it reads the project's other shown files by their paths; `GET /.loom/files.json` answers `{"files": [PATH…]}`, every shown file sorted, at an address no shown file can have since `.loom` is never shown; and its `quilt:`, `cited:` and `app:` links go through the bridge below. It has no way to write. Its browser storage lasts only until `loom serve` restarts, since the origin's port is chosen anew each time. Every answer from that origin carries `Content-Security-Policy: connect-src 'self' data: blob:`, so a page's scripts connect (`fetch`, `XMLHttpRequest`, a WebSocket, an event stream, a beacon) to that origin alone, and a player on the page whose script fetches its stream from another host does not play. The policy limits nothing else: a frame, an image, a video or a script from another host still loads, which embedded players need, and such an address can carry what the page read, so an HTML file in a quilt is still trusted as any program the person runs is. Into each HTML page it adds a small script, the bridge, that posts to the viewer's origin alone: a click on a `quilt:`, `cited:` or `app:` link, which the viewer follows as its own; the words selected, which the viewer reports to `here`; and a move to a new anchor. The viewer frames the page with `sandbox` keeping its origin but granting no top navigation, and drops every message not from that frame and that origin. Where no frames origin runs, a viewer shows the page from `/_files/` with no script.

**[decided]** **`open` never runs code.** It opens an application by a plain name (letters, digits, spaces, `.`, `-`, `_`; `open -a` on macOS, `gtk-launch` on Linux) or a shown file whose suffix is a document's — a notebook, a spreadsheet, an office document, an Anki package, audio or video, a book — and refuses a file with an executable bit, a hidden file, and any other suffix (`not-openable`, `no-such-file`, 400 and 404). An agent can write a file and a link to it into the quilt; it cannot make the person's click execute it.

## 6. The library's intake

One intake takes in everything a person adds to the library: files dropped anywhere on the viewer, a pasted text, and `loom library add` on the command line, which goes through the same function (`loom/src/loom/library/intake.py`) and reports the same rows. What it adds is a reference, a node of the library (`nodes.md` §7), and the documents a reference holds are kept by hash in `.loom/library/documents/`. Every endpoint here is the author's, refused to a declared agent with `author-only` (403).

**The library's generation** (`loom/src/loom/library/generation.py`) is one number that goes forward whenever anything a library read answers from changes: the library's nodes and the tags on them, every log under `.loom/records/`, the documents the store holds, the person's documents' citations and the labels their last compiles cite each work by; a publication that changes none of these leaves it where it was, so a compile alone does not set an open view reading again. It is the time in milliseconds at which the publisher first saw the library so, or one more than the last it gave, and never goes back. Every library read answers with it as `gen`, and with `since` equal to it answers `{gen, unchanged: true}`; every library write (`library-receive`, `-take`, `-answer`, `-undo`, `-unfile`, `-look-up`, `-entry`, `-delete`, `-restore`, `-upgrade`) answers with the `gen` it left; and the stream says each move as its event `library` (§1), so a viewer reads again what it shows once, whoever wrote: the publisher's watcher follows the library's node files and the records, so an agent's write from a shell is said too.

**A drop** waits in `.loom/local/incoming/<id>/`, one folder per file, which stays on one machine (`.loom/.gitignore`) and is never under `.loom/cache/`, which loom may delete. `<id>` is the file's sha256. While it waits it holds the file as `document.<suffix>`, the suffix of its kind (`.pdf`, `.bib`, `.tex`, `.tar`, `.gz`, `.zip`), so two receives of the same bytes keep one file, and `arrived.json` (`{name, size, when, not}`, `name` the name it was dropped under and read under, `not` the works it is known not to be); and, once a question is asked, `question.json`. When it is taken, `act.json` records what each act wrote, which is what `library-undo` reads, and `arrived.json` stays for as long as any act on the drop stands, so a drop that waits again after an undo or an unfile keeps its name and its `not`; the same bytes received again wait under the name they came with now and keep their `not`. A pasted line or BibTeX entry that is added, a dropped `.bib`'s among them, records its act the same way, in `.loom/local/incoming/<id>/act.json` under its row's `id` (`t-` and 16 hexadecimal digits of the hash of its text) with nothing beside it. **A drop lets go of its file only once its act is recorded, and only while these very bytes stand in the store and a reference names them**, so a crash never costs the only copy.

**A row** of a take or an answer is `{id, item, name, state, …}`, in exactly one of four states:

- `added`: the work is in the library, with `ref`, `short`, `title`, `authors` (surnames), `year`, and `found_by` (what the work was known by: `arxiv`, `doi` or `zbl`, an identifier it states or one pasted; `entry`, a pasted entry, a source's `\title` and `\author`, or the work a file was dropped on, whose entry it is filed under; `title`, a PDF's file name; or `none`), `tex` (loom holds its TeX source), `unconfirmed` (made from an identifier with no look-up), `identifier` (the first identifier its entry states, as `arxiv:2209.01234v2` or `doi:…`, which a look-up asks; null when it states none) and `under` (filed under a work the library had); `act` names the act that added it, a drop's or a paste's. `library-undo` with its `id` and `act` takes it out again.
- `here`: these very bytes are held, or for a pasted text the library has the work, by its key with the same entry or by an identifier it states, that very version of an arXiv number (each version is a work of its own, `nodes.md` §7; a number with no version is any of them): `ref`, the work's words and `why`. Nothing is written; a drop of bytes held lets its file go, and an act it recorded stays, so that act's undo stands.
- `question`: one question, "is this one of these works?": `question` (its id), `document` (`{name, kind, identifiers}`, what the file states of itself) and `candidates` (`[{ref, short, title, authors, year, how}]`, `how` the identifier the file states that the work states too, as `arxiv:2504.01234v3`, which the viewer words, and null for the work the file was dropped on when that work states none of them). Nothing is written but the waiting file. `library-answer` settles it.
- `cannot`: `code` and `why`: `not-recognised` (a text that names no work), `no-service` (an ISBN or a MathSciNet number, which loom does not look up), `missing` or `unreachable` (a look-up that found nothing or could not be asked), `key-taken` (a pasted entry whose key another work has, compared as check 9 compares keys, or an entry above it in the same text, which loom never renames), `has-document` (a file dropped on a work that holds one of its kind already), `not-a-source` (an archive or TeX file that is damaged, protected by a password, unpacks past 256 MB or past 10,000 files, holds a file and a folder of one name, two names a disk blind to case keeps as one or a name no disk holds, or holds no `.tex` file), `bad-name` (a file whose name holds a control character, a NUL among them), `refused` (an entry the checks of `nodes.md` §11 refuse). `why` names a work by its short name and an entry by its key, and says what in it to change, never a file of loom's. Nothing is written. A drop refused goes, since taking it again would say the same, except one refused `has-document`, which waits, listed `received` in `arriving`, since once the work's own document is taken off the same take files it.

A drop that waits to be taken is a row in a fifth state, `received`, `{id, item, name, state}`, `name` the name it arrived under; it is never the answer to a take. The manifest's `arriving`, present only while something waits, lists the waiting drops as rows: each in state `question`, or `received`; and `library-unfile` and `library-undo` answer with the `received` row of a drop that waits again.

**Nothing is filed under an existing work unless the person says it is that work**: `same` in an answer, which is the person's word and files under the work named whatever else the file states, or `for` on an item, a file dropped on the work's row, when the file states nothing against it. **A file is offered as an existing work only by an identifier it states**, never by its title or byline (the rulings of 2026-11-21 on `library-views.md` Opens 6 and 18): arXiv's stamp in a PDF's margin, an identifier set apart at the head or foot of its first page, or an arXiv number in the name it was dropped under, as arXiv names a source. A stated identifier that a work in the library states, compared as a DOI without case and an arXiv number without its version, asks the one question with those works as candidates; a work in the drop's `not` is never one. A file stating nothing the library has is a work of its own, whatever its title. A dropped `.bib` is taken as pasted text, a row an entry; in either, each entry has the `@string` abbreviations the text defines written into it, as gathering writes them (`nodes.md` §7), and an entry whose key an entry above it has is `here` when it is the same entry and `key-taken` when it is another.

**A work of its own** gets its entry by looking up the identifier the file states, when the quilt allows the network; else from what the file says of itself, a reference manager's file name for a PDF (`found_by` `title`) or a source's `\title` and `\author`, which a source states exactly, with the identifier, and the work is unconfirmed until a `library-look-up` finds it. A pasted identifier is looked up, or offline makes an unconfirmed work with the identifier alone. A work holding a TeX source gets its macros node from the source's preamble at once (`nodes.md` §8).

**The network, act by act.** `online` on `library-take`, `library-answer` and `library-look-up` is the person's allowance of the network for that one act, written nowhere; without it the quilt's `[library] online` decides, and an agent cannot give it, since these writes are the author's. While `[library] online` is unset, a take that does not say refuses `network-unasked` before it reads anything, and the received files wait; the viewer makes it again with `online: false`. A work then added from an identifier with no look-up reads `unconfirmed` and names its `identifier`, so its row asks whether to look it up this once, and a yes is `library-look-up` with `online: true` for that one work (`library-views.md`, Open 36). The same holds on a quilt with the network off. `loom library add` reads an unset quilt as offline and says so.

**Undo and unfile.** `library-undo` reverses the last act on a drop or a pasted row: an add (the reference it made, or the document it filed under a work, the document leaving the store when no reference names it; the drop then goes, or waits again, `received`, while an act before the add still stands on it), an unfile (the document goes back on its work, put back in the store from its drop when an add's undo took it out), or a drop still waiting (it is discarded). An add is the act's to undo while no node has been read from the work, and while the reference's file is what the act left; otherwise it refuses, naming what is in the way. Each undo, in whatever order the acts on one drop came, either leaves the store holding every document a reference names or is refused in a sentence. Taking back an add is recorded in the library's log as `undone`, which, unlike a delete, leaves gathering free to make the key again. `library-unfile` takes a work's document off it, the work staying with none of that kind and its macros node going with a source; the document waits again in a drop with that work in its `not`, so `library-undo` puts it back, and takes the work out of the drop's `not` again. The person's own file, wherever it was dropped from, is never touched.

**One lock for the library.** Each item of a take is decided and written under the library's lock, against the library as it is then, and so are an answer, an undo and an unfile; a receive waits on none.

**`library-receive` is the one request that is not JSON.** Its bytes are streamed to disk as they arrive, at any size; `application/octet-stream` is not a type a page of another site may send without asking first, so it keeps out what check 3 of §3 keeps out, and the token and the page it came from are checked as for every write.

## 7. The home server

**[decided]** `loom app` serves loom's home page, which opens, creates and lists a person's quilts, on port 8790, or on a free port when that one is held; it records its port, pid and address in `app/home.json` in loom's folder for the machine, which is trusted only while the home there answers `GET /_api` with that pid. One home runs on a machine: it holds `app/home.lock` while it runs, and a second `loom app` finds the first, says its address and exits. It holds no quilt. It serves the viewer it started with, as a quilt's server does, and none of a quilt's files: `/build/`, `/digests/storage/` and `/_files/` answer 404. Its guards are §3's: a request must name its own host and port, `GET /_api` and every write are refused to a page a browser says came from elsewhere, and every write carries the token and is JSON.

**[decided]** `GET /_api` returns `{"home": true, "pid": 4242, "token": "...", "capabilities": [...], "viewer": "...", "stale": false}`; `home` is how a viewer knows to draw the home page and not a quilt.

**[decided]** The home keeps a list of quilts, `app/quilts.json` in loom's folder for the machine, each known by a digest of where it lies (§1's `quilt`) and keeping one port for good: a quilt first seen already served keeps that port, a new one takes the first port from 8800 that no quilt was ever given and no other program answers on, at 127.0.0.1 or `::1`, and a port is never given to a second quilt, since a viewer keeps its preferences per port and its layout per port and quilt name. A list that is there and cannot be read is kept as it is: the home lists no quilt, says `list: "unreadable"`, and every endpoint that would read or change the list answers `list-unreadable` (409) until it can be read. `loom serve` with no `--port` takes the port its quilt keeps. Each quilt the person opens is served by the unchanged `loom serve --port PORT --quilt ROOT`, in a process of its own, which the home finds again by its port answering `/_api` with its quilt's id, and stops at the `pid` it gives there. It starts again a server that died unasked after 2, 10 and 60 s, and then shows it as failed; one that refused to start (exit 2) is not started again; one quilt the home cannot serve is that quilt's failure, and the rest stay served. It restarts a server whose `/_api` says `stale` on the same port once loom's code has been still for 30 s, and then starts itself again once no quilt is being made. When it starts, it serves every quilt the person left open.

| endpoint | body | answers |
|---|---|---|

**[decided]** **A drop** waits in `app/incoming/<drop>/files/` in loom's folder for the machine, outside every quilt and never under a cache, until a quilt is made from it, or for 14 days after it was last added to. One archive dropped alone (a `.zip`, a tar, compressed or not, or one gzipped file, as arXiv serves a paper of a single file) is opened once into `unpacked/` beside it, judged by what it holds and not its name: nothing in it may land outside, a link may not point outside, and it holds at most 1 GB in 10,000 files. The paper's main file is the one an arXiv source's `00README.json` names as its top level, else the one `.tex` holding `\documentclass` and `\begin{document}` outside comments. The quilt is made with no tutorial `README.md` and opens on the paper (`[quilt] home`); the paper comes in through the import's one act with every theorem-like `\begin` and `\end` put on its own line in the drafted document, and the paper as received is kept as it came. A paper that does not typeset still comes in (`typeset: false`, `untypeset` the first error); a drafted document that does not typeset as the paper did comes in too, unchecked, with `differs: true`. A `.tex` or an archive dropped on an open quilt is the library's (§6); the home's drop is how a person's own paper makes a new quilt.
