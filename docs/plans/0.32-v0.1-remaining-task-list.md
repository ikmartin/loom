# v0.1: the remaining tasks

A companion to `0.32-v0.1-status.md`. Each task below can be picked up alone by a fresh agent. A task whose "Depends on" tasks are all done may start; two tasks may run at once only if neither lists the other under "Collides with". Sizes are estimates from the pace of 2026-11-24: S is a few hours of one session, M about a day with one review look, L several days. Tasks marked **yours** are the author's own and no agent can do them. A task's heading ends in **done** with its date once it has landed or been answered, and in **in progress** while a session works on it.

## How to work a task

- **Start from** the branch the task names, in a worktree of your own, on a new branch `task/T0xx`. Never work in the main checkout, never move the local `main` ref, never push.
- **Read first** `AGENTS.md` and `CLAUDE.md`, then what the task names. The lanes' notes of 2026-11-24 are not in the repository: they are copied, on the author's machine, to `.claude/v01-notes/` under the main checkout, which is `$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")/.claude/v01-notes`. Each lane's hand-over opens with a short "Where … stands".
- **Build** in small commits, each with a test that fails without it. Commit no generated file and do not vendor the viewer.
- **Test** only what each commit touches: its own tests and the ones it adds, with svelte-check, `scripts/checks/words.py` and `scripts/checks/hardwrap.py` where the viewer or prose changed. A commit that adds a command, a writer, a path in the quilt or a viewer section also runs the repository's guard tests, which take seconds and caught every red landing of 2026-11-26: `test_one_door.py`, `test_output.py`, `test_paths.py`, `test_help.py`, `test_mcp_tools.py`, `test_cli_reference.py` and `test_reserved.py` (after `scripts/regen` for the two generated ones). Run no whole suite or lane before handing over; CI on the landing's push is the one whole run of a task (decided by the author on 2026-11-25, since breaking things at this stage costs little). Every run of loom outside the tests has HOME and the XDG folders in a scratch folder.
- **Hand over** in a few lines at the end of the task's branch description or in a note beside the others: what is done, what is not, what was run.
- **Review:** where a task says "Review: yes", one look by a fresh agent with a narrow bar before it lands; otherwise the diff is read.
- **Landing a finished task** is its own small step: merge onto the integration branch, `scripts/regen`, vendor the viewer if viewer source changed, push, then read GitHub's CI for that head, which runs the full lanes for the codebases the push touched. A red job there is a failed lane, fixed before the next task lands, so that each push says which task broke what. No local `scripts/verify full` runs per task (decided by the author on 2026-11-25): it runs on this Mac only before T005 and before the release, for what CI cannot see. This Mac's lane runs Python 3.13 on a case-insensitive disk with its own fonts; CI runs Linux under 3.11 to 3.13.

T005 is done: the integration branch is `main`, and a task starts from `main` wherever it names `library-web`.

The tasks are numbered so that a task depends only on tasks with smaller numbers. They are listed in that order, each with its area.
