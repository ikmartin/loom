# The model

What loom works with: the quilt, its documents, the nodes and graph read from them, the history, review and trust, annotations, the library of other people's work, notes, sessions, and the viewer that shows all of it. Formats are in `docs/specs/`; commands are in `loom --help`. This file says what the things are and why.

## The quilt

A quilt is a research project in a directory marked by a `config.toml` with a `[quilt]` table; every command finds it by walking up from the current directory. It may hold several documents, one, or none at all. A paper with a talk beside it is a quilt; so is a reading project with no draft, made of the papers and books someone is learning from.

What lives where:

- **The author's sources:** documents, node files, style files, the bibliography and figures, wherever the author keeps them. A document's files sit in its own directory or below, because a document compiles from its own directory (P12).
- **`.loom/`** holds everything loom writes, in a folder for each of five kinds, with `format`, the layout's number, which a loom reads first and refuses a quilt by when it is not its own. `records/` is what the person and loom decided or said: the acceptance ledger, the history (the default of `[quilt] history`), `annotations/log.jsonl`, the annotation log, `annotation-types.toml`, the quilt's annotation types, `edits/log.jsonl`, the suggested edits, the review and adoption decisions, the looks, the library's log, and `retired/`, sources `atomize --retire` set aside. `library/` holds the library: its nodes, a file each (`nodes/`), and the documents its works hold, by hash (`documents/`). `agents/` holds the agents' places: `instructions/`, what they are given; `sessions/`; `copies/`, the documents the author and an agent both edit (below), made when the first is; and `scratch/`, each session's intermediates on this machine. `local/` is this machine's state: the server's address, the journal of loom's writes, where each agent last looked, files dropped and not yet filed. `cache/` is everything derivable, which can be deleted at any time: `site/`, what the viewer is served, `tex/`, one compile folder for each document, and `blocks/`, rendered blocks by key. `loom/src/loom/paths.py` names every entry.
- **`research-state.md`** at the root (the `research_state` setting) is the research state, written when an agent first keeps one.

**How long each kind is kept.** Records are never deleted by loom, and the library only when the person removes a work. After a build that published, once the server is at rest (at most once an hour) or at the end of a whole `loom build`, loom removes from `.loom/cache/` whatever the build as it stands does not name, the compile folder of every document no longer in the quilt among it; a build that published with errors in the documents sweeps as any other, and one that stopped before it published removes nothing. The test is the build's own index, which names every file it published or wrote into the site and every cache file a fragment it holds was made from, and never what a build happened to read, since a build that re-renders nothing reads little; a sweep looks at the cache only while the index on disk is the one its own build wrote, so after another process's build it waits for its own next one. No earlier generation is kept, so going back to an older loom costs a cold build. A served quilt also keeps in memory what its builds derive and will derive again, mostly in `loom/src/loom/scan/memo.py`'s memos: each piece is looked up by everything it is made from, and let go once a build no longer asks for it, so what the server holds follows the quilt as it is now and not how many saves came before; a forced build forgets all of it, and so does a build after one in another process, and what was made while TeX or a figure converter failed for the machine's sake is kept for no later build. What is made when someone asks rather than by a build is kept while what it is for is there: a key's closure while the key is, a crop of a PDF's page while an annotation in the log was written on that page of that copy, a stored PDF's page text, section map and word boxes while the library holds the PDF, the rendered sides of an incorporation's preview while the preview waits to be applied, a picture while a page the site serves or keeps names it, and a comparison's pages and a draft's preview in its paper for fourteen days after a request last named them; the word boxes of a PDF outside the store, made when a mark is drawn or asked for, are kept only while a build reads them. Nothing written in the last hour is removed: that keeps what a step or another process has just written and not yet named; a build in another process that has been running for more than an hour is not covered. An agent's scratch goes fourteen days after its session's last write, in its session's directory, its run log among them, or in the scratch itself; each result of a call that names no session, in `scratch/none/`, fourteen days after it was written; and a saved preview of an adoption or an incorporation when it is applied, or fourteen days after it was written. Nothing is removed for its size: `loom doctor` reports the size of each kind, and names a session whose scratch is over 500 MB with the day it goes. The same sweep removes the expired scratch and previews. It removes only under `cache/`, `agents/scratch/` and the two folders of saved previews, and never in one that is or holds the history, whose setting the loader refuses there anyway; it removes each file by its name in its folder, opened from the swept folder one step at a time without following a link, so a folder swapped for a link while it works is never entered, and it leaves whatever changed after it looked. A tool TeX unpacks on its first run, `biber`, about 200 MB, is unpacked once for the machine, in loom's own place outside every quilt (`loom/src/loom/machine.py`), whatever temporary folder a run is given; one copy stays there for each `biber` that ever ran, which `loom doctor` reports and nothing prunes. A run that cannot write that folder, an agent's sandboxed shell among them, unpacks a copy of its own in its temporary folder: outside the quilt unless the agent points it inside, in its scratch, where it expires, if the agent points it there, and kept for good if it points it into its session's directory. No agent is let write the machine's folder, since the person's own runs execute what is in it. The viewer a server serves is kept in that folder too, one copy of each version for the machine (`machine.viewers`, about 11 MB a version), shared by every server of that version and marked held by each: a server holds the version it started with, so vendoring a new viewer changes nothing a running server serves. A copy is made aside, from a viewer that did not change while it was copied, and put in place whole, and a version is removed by being moved aside first, so a copy cut short, in the making or in the removing, is never served. Each server that starts removes the marks of servers gone and every version no live server holds, touching only what has the shape of what loom keeps there, and nothing reached through a link; a server stopped, cleanly or outright, leaves its mark, and the copy where it held the last mark, until then. A server does not start, and says what stopped it and where, when it cannot write that folder, when its viewer changed each time loom copied it, or when its version's name there is taken by something loom did not make.

`loom init` writes `config.toml`, a README that teaches loom, and `.loom/`, and nothing else. Every `.tex` file is scanned except under `.loom/` (whose agent copies are read on purpose), the history and sync directories, tooling directories, and files whose first twenty lines say `% !LOOM ignore`. Nothing is inferred from where a file sits (P5); the exclusions are exclusions, not inferences.

**Open.** A quilt still assumes a paper in places: `status` counts "keys of yours". For the Learner, a quilt with only works and notes must be complete and unremarkable (not built yet, see [README](README.md#decided-not-yet-built)).

## Documents

A **document** is a `.tex` file with `\documentclass` anywhere loom reads, unless it is ignored or superseded. Every one is **live**: scanned, compiled, rendered and reviewable. There is no list of documents; the files are the list. A document is named by its path without `.tex`, kept as a path (`paper/main.tex` is `paper/main`), which keys its rendering and its address in the viewer, so two documents may share a file name in two directories; its compile folder, `.loom/cache/tex/<stem>-<hash>/`, is named by its file name and a hash of that name, so a person finds a document's PDF by its name and two of one file name never share one. A document compiles from its own directory, so its `\input`, figures and bibliography are named from there and none reaches above it with `..`, and a node it reaches is numbered from that document's own compile. Its macros come from loom's marked block in its preamble, or from a `loom.sty` kept beside it. A document is read as TeX makes it: the viewer shows the HTML its compile made, with each node and block placed in the source by its words; after an edit, that HTML until the next compile, with each edited statement made again by TeX; and, until a compile has made any, or when its page lost a statement TeX4ht set where loom cannot find it (beamer's frames), its source, node by node, never an approximation of what TeX would print. Text no compile makes, a node no document reaches, a landmark, a comparison or a proposal, is made by TeX too, as snippets under the preamble of the document that owns it. `[quilt] main` names the **default document**, whose preamble and engine loom reads for its LaTeX work; unset, it is the only document, or none when there are several. `[quilt] home` names the **front door**, the file the viewer opens on when it remembers no place; unset, it is the quilt's `README.md`.

**Open.** Nothing limits what a document reads when it compiles: it can `\input` any file the person can read, by its absolute path, and print it into its PDF and its HTML, so a cited paper's source or a co-author's file can carry the person's own files there. TeX Live's setting for this (`openin_any`) has no effect from TeX Live 2026 on, where every read is allowed, and before that it also refused the documents loom keeps under `.loom/`, so loom does not set it. What loom does hold every TeX program it starts to, whatever the person's configuration or shell says, is writing only in or below the directory it runs in and running no command but those TeX Live lists as safe. TeX's own configuration offers no way to close the read; on macOS loom closes it by fencing every compile it starts ([agents.md](agents.md#what-only-the-author-may-do)).

An **agent document** is one the history records as an agent's, kept in `.loom/agents/copies/`. It is a flat copy of one of the author's documents, made by `loom draft DOC --ai NAME`, or of one labelled section and its descendants with `--section ID`, with every id it defines derived (`rl-0004-ai` for `rl-0004`) so it can never collide with the author's. Agent documents of one document may coexist when their scopes are disjoint: a whole-document copy overlaps every section and a section overlaps its descendants, and a section copy, or any later copy of a document, derives its ids with a numbered suffix never reused (`rl-0004-ai-01`). A section copy reads the rest of the paper in the context saved when it was drafted. The copy records the version of each node it began from, so loom can say when the author's side has moved past it (`loom ai drafts`) and refresh it (`loom ai refresh`). `loom ai close` retires one, keeping its text and annotations in the history and freeing its scope, and `loom ai reopen` brings it back. Nothing in an agent document is accepted or published. Taking its changes back is `loom adopt`, the author's act: it previews the changes, lets the author choose node by node, and the prose and the preamble each as a whole, stamps the working document first, and then writes (P7). A result both the author and the agent changed is merged line by line, and offered as merged when the edits fall apart; when they clash it can't be taken until it is reconciled. In the viewer, Review's Proposed edits opens a copy's review on a page of its own, which is one pass: each change is taken or left in a bar that stays put, a block can be marked as checked so its acceptance is recorded as it is written in, and one Apply writes what was taken. An update from Overleaf takes the project's text in whole, and Results to accept lists the blocks others changed. A document written into `.loom/agents/copies/` by hand, which no step made, is refused by `loom lint`. A document of an agent's own (a survey, a section to be placed later) needs no command: it is a file the agent writes where the quilt lets it ([agents.md](agents.md)), and is a document like any other. A copy is the way to work on a document the quilt protects from agents, or to give the author changes to choose among before any lands.

A **landmark** is a document as it stood at a moment worth returning to, and is a **version** of it: the paper as received by `loom import`, a working document kept by `loom stamp DOC -m NAME` or recorded by name in the viewer, and the version loom keeps at each of the author's acts on it (a change kept or undone, changes taken in, a restore). It keeps the document's flat text and, for a version kept now, each of its files' text. It lives in the history, is never scanned, and so defines nothing and collides with nothing. In the viewer each document's versions can be paged through, compared with now, and put back, the text a restore replaces kept as a version first; `loom history show` prints one, and `loom history restore` starts a new working document from it.

A conversion (`atomize`, `linearize`) records that its output **superseded** its input, which stops being scanned until `loom live` says otherwise. `loom mv` records a document's move, and every record naming it by path follows the move when it is read, without being rewritten.

## Nodes and the graph

A **node** is a theorem-like environment (declared by `\newtheorem`) or a section. It becomes addressable when its first label is id-shaped, `<prefix>-<local>` such as `rl-0004`; `loom id` prints the patch that adds one. Other labels on the same node are aliases. A **key** is what review is about: a statement (its id) or a proof (`rl-0004/proof`, `rl-0004/proof/2`).

An id is **defined once**. A file may be included by several documents, and its nodes then appear in each, numbered by each. But when an id is defined twice, by two files or within one, the key is **conflicted**: it has no text, loom reports both definitions and chooses neither, and `loom fork` gives one of them a fresh id. Loom never picks a winner, because any rule for picking one would let one definition's acceptance and annotations silently apply to another's text. An id that history has recorded is never allocated again.

**Edges** are read from what the author writes: `\ref` and its relatives, and `\uses{…}` for a dependency the text does not name; a citation names a work and is no edge. The **closure** of a key is everything its statement depends on, transitively; `loom source KEY --closure` prints it as the exact context for reading, reviewing or drafting that key. A node no document reaches is **loose**, which is computed, never a directory. `% !LOOM see: ID` links two nodes for the reader and is never a dependency.

Two markers carry mathematical status in the source: `\incomplete{…}` marks a statement or proof as not finished, and `% !LOOM basis:` declares why a block may be relied on (a local proof, a cited result, an assumption, an open claim, or exposition). The exact rules are `docs/specs/source-contract.md`.

## History

The history (`.loom/records/history/`) records what loom was told, at the moments it was told: never on save, and never a claim about the filesystem (P13). A **step** is an import, a stamp, or the copy behind an agent document, numbered once across the quilt; each act of the author's that keeps a version (Review's Keep and Undo, taking changes in, recording one, restoring one) is a stamp of the document it concerns, unless the document is as its newest version holds it. Keep and Undo also write a line naming the file, so Review › History lists every act. Every act that writes a person's file (Keep, Discard, restoring a version or a set-aside text, a tick, Settings) goes through one door, which journals it before the file, keeps the bytes it replaces and settles a write a crash cut short (`writes.md`). A stamp records every key whose text moved since the last step; given a document, it also keeps that document as a landmark. A key's text at a step is a **version**, addressed `rl-0001@3` or `rl-0001@submitted`.

`loom revert KEY@N` prints the patch that puts a version back and records nothing, since the head's text says whether it was applied. `loom fork` gives one document its own copy of a node under a new id. Every divergence between the record and the files (an edited landmark, a missing step, an unreadable ledger, a step interrupted before it was recorded) is reported with the command that resolves it, and nothing stops a build. No step is recorded beside an interrupted one: every command that records a step refuses until its directory is removed.

## Review and trust

Two kinds of record say what has been looked at, and they never mix.

**Acceptance** is the author's claim that a key's mathematics is right. `loom accept` appends a row to the ledger (`.loom/records/state.toml`) holding hashes of the key's text, of every statement in its closure, and of the preamble, with snapshots of that text. A row is a claim about exact text, so it goes with that text as a record does (`writes.md`, "Where a record goes"): it records what told its block from others (`context`, one JSON string in the row), follows a block put in before it that renumbers its key or a label moved off it, and is on no block where nothing says which. A row written before `context` was recorded stays on a stable key's block. Only the author accepts; an agent is refused whatever name it gives (`agents.md`). From the ledger and the current text, every key's state is **computed** (P3):

- `incomplete` when it contains `\incomplete`, whatever else is true;
- `accepted` when the latest row's hashes still match;
- `accepted, stale` when something has moved, with each cause named: its own text, a dependency (directly or through another), the preamble, its basis, or the document it was accepted in. `loom status --explain KEY` shows the diff;
- `conflicted` when two live files define it;
- `draft` otherwise.

On top of these, `proved` and `settled` are display states: a statement is proved when it and a proof are freshly accepted, and settled when everything it depends on is settled too. A cited result is a settled leaf by attribution.

Acceptance is personal: each reviewer's latest rows are their own, and a coauthor's acceptance never accepts for you. In the viewer, Review's Results to accept lists every block of the person's documents not freshly accepted, in dependency order, as changed since accepted, taken in from a copy or from Overleaf, or, folded and uncounted, never accepted, each opening to what changed since it was accepted; **Accept** records an acceptance at once, for one block or a selection, and what loom cannot accept says why before anything is pressed. Overlooking a block never accepts it.

**A look** is the third thing Review keeps, and it says nothing about the mathematics: the text of every open file agents may edit (one the viewer shows that is text, LaTeX included and LaTeX's auxiliary files left out, and not one it draws as a picture, such as an SVG, whose change would be drawn as markup nobody reads, that no `[agents] deny` entry or protection keeps from agents, and that lies in no Lake project, the research state included since agents keep it through loom) as the person last saw it, kept in the history's texts and recorded by their name in `.loom/records/looked/`. It is always kept. A place agents are denied is the person's own, by the same rule the door and the agents' permission files read (`agents.denied_by`), so a change there is never listed and is not tracked, an agent's made against the deny in an app no permission file holds to it included (`agents.md`, "Where an agent may write"); `loom init --from`, `loom import` and the demo deny agents the paper they bring in, so a person's saves in the paper leave no row; everything outside it is open to agents from the start, so a save there, the research state's among them, is listed whoever made it. A Lake project, a folder below the quilt's root holding a `lakefile.toml` or a `lakefile.lean`, is the agents' own: the look leaves it out as the scan and the watcher do, by the one test `scan.source.lake_root`, so the Lean an agent writes there and the paper's files the skills' linters copy into it are never listed. Review and `loom changes` name the places left to the person, the config and each deny entry, so an empty list is not read as nothing having changed. The look keeps the deny list it was last brought to: a file opened to agents since goes in as it stands, and one closed to them keeps what the look held, so a change waiting there is listed again if it is opened, and a file renamed while its place is closed is found by the text it held as the place closed, so an agent's new file or waiting change there is listed at its new path. Where agents may edit, loom cannot tell who changed a file, so a change there is listed whoever made it, which is what opening a place to agents means; what the person does through loom is not, since every act of theirs through the door puts what it wrote into their look (`writes._follow_look`), merged in by lines where another change waits in the same file and left out where the two meet, and an agent's act never does. The name is the person's as one resolver gives it, once per process: `[author] name` in their own configuration (Settings › Profile), else git's `user.name`. A look and an acceptance are kept under that name, so Review and `loom status` say when git gave it. A name with no look of its own, as after the person sets theirs in Settings, is given the newest look the quilt holds, kept under the new name with whose it was (`carried`, said in Review and `loom changes`): a fresh first look would take in unseen every edit waiting since. What changed in those files since, whoever made it, is cut into **changes** word by word (difflib's diff of the two word lists, found faster and exactly: `pending.cut`, with today's diff kept beside it as its oracle), and with the suggested edits waiting to be kept they are what is pending. The document draws them where they are: in Markup removed words are struck and new words underlined in teal, a colour annotations never use, and Final shows the text with every change made. Each change has **Keep** and **Discard**, and the Changes menu keeps or discards them all; Review's Proposed edits lists the same changes across the quilt, a row for each suggested edit and one for each file edited in place, which opens to a card for each of its edits with Keep all and Discard all for the file, with a To do that adds the open annotations of others. The cut runs after every save and again, under the writes' lock, at a Discard, a Keep and the viewer's Accept, so an act listed before another moved the look or the file does its work on what is there now, or refuses a change no longer there, and never writes at a stale place: a change, or the same change on every line, costs well under a second in a file of 20,000 lines; what still costs seconds is many changes among lines of varied length, a macro renamed across 20,000 lines of prose taking about 15 s, since each step of the diff searches again what lies between the runs it has found. Keep takes an agent's change into the look, or writes a suggested edit into its file and the look; Discard writes a change's old words back, keeping the text now in the history first (P7), or discards a suggested edit, and discarding a file new since the look removes it. Keep carries every annotation on the changed words onto the new words, marked as written on earlier words, an annotation whose words were all removed stays as a mark at that spot, and keeping a change that answers an annotation resolves it. What is current is what the person has kept, so an annotation written before an agent's change stays on the words it was written on until the change is kept or discarded. Accepting a block in the viewer also keeps the changes touching only the blocks accepted, since the page showed them; keeping accepts nothing, and `loom accept`, which shows no edit, leaves the look alone. A box ticked in the viewer goes into the look as it is written, since the person just made that change. Keep and Discard are the author's (`agents.md`), on the command line `loom changes --keep` and `--discard`, and `loom serve` takes the first look when it finds none, so an agent's first edits are caught.

**Annotations** are the other kind of record: what anyone, person or agent, says about the text (next section). Annotations never change a state; a key with forty open revisions and a fresh acceptance is accepted.

## Annotations

An annotation is the one record of what anyone, person or agent, says about the text, filed only by `loom annotate`, which the viewer's writes call too (P4), and kept in `.loom/records/annotations/log.jsonl`. It may be a mark on words, a comment at a place, a mark drawn on a PDF page, or something said about a whole key, document or work. It has an author (a person, or an agent naming itself), a time, a target, and the version of the text it was written on; it belongs to no session.

An annotation is drawn in its own **look**: one of nine colours (grey, brown, red, orange, yellow, green, blue, purple, pink), a style (underline, highlight or strike), a thickness in whole pixels and an opacity. Loom gives a colour no meaning (A4).

A **type** is a preset of the quilt's, kept in `.loom/records/annotation-types.toml`: a name, a look, whether it stays open until resolved or only informs, and instructions that tell an agent when to use it. `loom init` writes the file with the defaults listed, `loom upgrade` adds it where it is missing and never rewrites it, the person edits it in Settings, and an agent may edit it too. The defaults:

| type | look | for |
|---|---|---|
| Revision | red highlight, 65% | something is wrong and must change; how serious is said in the comment |
| Suggestion | orange highlight, 60% | nothing is wrong, but it could be better |
| Question | blue highlight, 60% | something the writer could not decide |

Types are optional. Having no type is called **Plain**, which is what an annotation that only informs has, and the file's `[plain]` sets the plain look an untyped annotation is drawn in unless it sets its own (a yellow highlight by default), so loom, an agent and the viewer draw an untyped annotation alike. An annotation names its type by a fixed id and keeps its look, so renaming a type touches no annotation, and deleting one leaves its annotations untyped and looking as they did; no interface depends on a particular type existing. An agent is given the types by `loom ai orient`, generated from the file, and the MCP server's instructions name each one; a mode names a type by a placeholder that loom fills with its current name.

Only an annotation whose type stays open until resolved is **open**, has Resolve, and is counted by `loom status`; an untyped annotation never is. One that is resolved is hidden until the reader asks for resolved annotations (A6). **Deleting** removes an annotation and its replies from the log. An agent deletes only its own, and deleting by author or by version (`loom ai delete`) is the person's. When the person deletes an agent's annotation, that agent's next `loom since` says so once, from a line under `.loom/local/since/` that is never committed, and then forgets it.

A **suggested edit** is a record of its own, beside annotations: words on a key, or in a Markdown file the viewer draws, replaced with new ones, with a comment if it needs one and the annotation it answers if there is one, written only by `loom suggest` into `.loom/records/edits/log.jsonl`. It takes exactly the quoted words' place, or goes right before or after them; one with no quote is about the key's body, and one on a Markdown file always quotes words of it as written, found once in the whole file, with the words either side of them standing as when it was filed. It is pending beside an agent's changes to open files and drawn with them (above), and `loom changes ID` prints the patch that takes it. Keeping it is the author's act: Keep, in the document or in Review, or `loom changes --keep ID`, writes it into the file, keeping a version of each document it changes first, and records it kept; Discard, or `loom changes --discard ID`, records it discarded and leaves the text alone; an agent withdraws its own with `loom suggest --withdraw ID`. An edit the author made by changing the source instead reads as taken, and keeping it then writes nothing; so does one whose text is in already with the author's words worked into it, since writing it again would put in a second copy. An edit is written into a person's file, so where it may go is held to more than an annotation's place is. The words it quotes must lie inside its block: words that reach the block's `\begin{…}` or `\end{…}`, or that run across a block inside it, are refused when the edit is filed, and one filed before that is unplaced. And a key named by its place in its file, as `#proof:3`, names another block once one is put in before it, so an edit on such a key records the line above its block beside the block's text, and goes on the one block of the file that holds that text; among several that read the same, on the one under that line; and once its block has changed, on the block at its place only if it quotes words and the line above still stands, where its quote must then stand. Otherwise it is unplaced, says why, and Keep writes nothing. A block that reads the same as another under the same line takes no edit by its place. **Open.** An edit on the body of an unlabelled block is unplaced as soon as the block changes, by the person's hand or by another edit kept on it, though nothing moved; telling that case from a block put in above needs a record of the words around the place, which records do not yet carry. Several edits on one key are placed together, and one on words another already changes waits. An edit on an agent's copy is not kept: it comes in with the copy. The viewer calls it a suggested edit, never a suggestion, since Suggestion is a type (K7).

A **target** is a key, a labelled equation, a whole document, a cited work as a whole or one of its pages, a page of a project PDF, or a Markdown file the viewer draws, by its path. An annotation on text is anchored by a quote: the exact words, with a little context before and after, resolved inside the target's own text, so moving text between files never moves an annotation. In a Markdown file that text is the file as written, and words a reader selected on its page are found there as the page prints them, without the markup's asterisks, backticks and link addresses. When the quoted words are gone, the annotation is **detached**: never drawn at a guessed place (A3), listed with its quote. A re-check edits its own earlier finding rather than replying to itself.

How an annotation is drawn is the A set of `principles.md`: its own look, a shape for what it is attached to, and a mark that never splits a formula.

**Open.** Annotations can target only addressable things today. Something said about an untagged statement, or about an open problem that is not yet a node, can only be said about the key or document around it.

## The library

The library is the works a quilt holds. A work is a **reference**, a node of the library (`<prefix>-XXXX-ref`, a file in `.loom/library/nodes/`) whose body is its BibTeX entry, and it holds the documents a person gave it, a PDF and a TeX source, each stored by its hash in `.loom/library/documents/`, which never changes once written. A work is named by its reference or by the key its entry has; an identifier its entry states, a DOI or an arXiv number, is data in the entry, by which a `cited:` link finds the work and a dropped document is offered as it. **Gathering** makes a reference for each entry of a bibliography a document or a landmark reads: after every build, the publisher's and `loom build`'s, when `loom stamp` or `loom import` makes a landmark, and before `loom library add` takes; reading the list of works makes nothing. An entry loom cannot keep as a work is left out and said to the person at its line in their `.bib`. A work is also added by hand, through one intake: `loom library add FILE...` takes PDFs, `.bib` files and TeX sources, and the write API's intake, which a viewer's drops and pasted identifiers are to go through, calls the same function (`docs/specs/write-api.md` §6). A document is filed under a work the library has only on the person's word, and offered as one only by an identifier it states, never by its title or byline; any other is a work of its own, its entry looked up by the identifier it states where the network is allowed, else made from what it says of itself. Loom uses the network only where `[library] online` allows it or the person allows it for one act, which an agent cannot do. Each act of the intake is undone in one step, the write API deletes a work with one undo, and the library's log (`.loom/records/library/log.jsonl`) says what was done. A stored PDF's page text, section map and word boxes are drawn from it the first time it is read, into `.loom/cache/library/pages/`.

An annotation on a work names its reference: `loom annotate REF`, or the key its entry has, on the whole work, or with `--page N` and `--quote`, `--box` or `--stroke` on one place of its PDF; `loom status --reading` lists them, and `loom link WORK` prints a link to the work by its reference, `quilt:REF`, with `--page` and `--quote` for words on a page of it. Nothing yet makes a statement or a proof from a work, so a quilt's results are its own and a `\cite` is no edge. The library's design, which the rest waits on, is [`library.md`](library.md), and its files are [`docs/specs/nodes.md`](../specs/nodes.md). `loom upgrade` brings a quilt an earlier loom made forward, its library carried into references (`loom/src/loom/library/carry.py`).

**Open.** The library's references are gathered from what the documents and landmarks cite, or added by hand. The Learner reads works nobody cites, so a work that is read must be as first-class as one that is cited: a work added by hand is a reference like any gathered one, and the Library lists it with the rest; what else the views show of a work nobody cites, of which loom digests nothing by its own hand, is not decided yet (see [README](README.md#decided-not-yet-built)).

## Notes

A **note** is a file of the person's own: Markdown, org or any text, written in their own editor and kept anywhere in the quilt. Loom does not edit it and gives it no format; it reads the `quilt:` links in it. A note is how exploration and learning leave a trace that outgrows a remark on one place: an explanation of a definition, an example, an attempt and why it failed, a connection between two works, a zettelkasten of one's own beside the quilt's resources.

- **An annotation is a remark on a place; a note is a file that points at places.** Annotate stays the capture that costs one gesture (P14), drawn where it was left and carried with its words when a change is kept. A note is the person's, may point at many places, and outlives loom. No annotation type is a note; Plain covers an annotation that only informs.
- **A note's link carries its words.** A `quilt:` link to a place in a document, a project PDF, a Markdown file or a work carries the quoted words with a little context (`quote=`, as a `cited:` link already does), found again as an annotation's words are, so it opens at those words and lights them. A page with no text, a scan or an image, is linked by its page and a box on it. Loom never rewrites a note, so a link whose words are gone is listed in Problems (`loom:link-words-missing`), as any broken link in a person's Markdown is. An editor follows a `quilt:` link with `loom open LINK`, run inside the quilt, which opens the viewer there.
- **Notes beside an item are the files that link to it.** Loom indexes every `quilt:` link in the files the viewer shows, raw links in plain-text files such as `.org` among them, and lists beside each document, work and PDF the files that link to it, each opening at its link. The list is computed and nobody edits it (P3). Any file counts wherever it is in the quilt; the notes directory says only where new notes go.
- **Selecting words opens actions.** A button stands at the end of a selection, on a document's text and a PDF's page alike, and a click on it, never a hover, opens Quote, Ask your agent, Annotate and New note, leaving the words selected; words Annotate's tool has just marked keep Quote, Ask your agent and New note beside Add comment. New note is also in an item's toolbar, for the whole document, result, work or file. Quoting is not a record: it hands the words and where they came from to an agent, as highlighting part of a reply does in a chat, and until an agent's session can take a quote directly, it is copied with its place.
- **New note runs the person's command.** Settings › Notes holds the notes directory, picked from the quilt's folders and kept in the quilt's config (`[notes] dir`, `notes/` unset), so it travels with the quilt; and the new-note command, kept in the person's own configuration for each quilt (`notes.toml` beside their own `config.toml`, by where the quilt lies), never in the quilt's, where loom ignores one, because a command run at a click must never arrive with a repository or be set by an agent ([agents.md](agents.md#what-only-the-author-may-do)); a new or changed one is kept only when the person confirms it in a dialog loom opens outside the browser. Loom splits it as a shell would and runs it with no shell, given the link, the quoted words, a name for the place, the directory and the quilt (`{link}`, `{quote}`, `{title}`, `{dir}`, `{quilt}`), each replaced inside its own argument, or all together in a JSON file whose path it is given (`{request}`), since an editor that evaluates what it is passed (`emacsclient -e`) must never have quoted words spliced into code; the command makes the file, so an editor's own capture template and ids work. With no command set, loom writes a Markdown note holding the link in the notes directory and opens it with the system's default app. The "All notes" tab in Docs lists every file that links into the quilt, with the places each links to.

Written for notes as annotations, and not yet decided for note files (each may move to note files or go):

- **Claims carry their evidence.** A note that claims something says how far it has got (conjectured, tested on examples, sketched, proved here, refuted), and every step past conjectured names its evidence. Who linked the evidence is shown, because a link is itself a claim (P15). Evidence is asked for when a note is promoted, not when it is taken.
- **What is worth keeping is promoted** to a node in a document of the author's (a problem, a lemma, a definition restated in their own words). Promotion is where care is asked for.
- **Open problems are nodes.** A question the Explorer is working on is a `question` or `conjecture` environment in a research document, with an id, edges and a computed status, and the attempts and dead ends about it attached as notes. An agent proposes one as a node in an agent document.

**A mark** (plan 0.28) is an annotation on a page of a PDF, a project's or a cited work's: words drawn in its look, or a pin that holds a comment, ink, words on the page, a box, an oval or an arrow. It is what Preview and Skim give a reader: one press, there later, with a comment if it needs one, moved, changed or deleted at will, with undo. On a PDF page the viewer's toolbar is a document's, with the PDF's own tools beside it: ink, words on the page, a box, an oval and an arrow, and Comment leaves a pin. An agent reads a person's with `loom since`, and may draw its own with `loom annotate FILE --page N --mark TOOL`.

**Loom's log is where a mark lives, and a PDF is what it is exported to and imported from.** A work's PDF, stored by its hash, is the document its anchors were checked against and never changes, a compiled PDF is replaced by the next build, and a mark in the log reaches coauthors and agents where one inside a file would not. So a mark never touches the file it is on. "Save a copy" writes a PDF with the marks in it as real annotations, after the file's own unchanged bytes, and this runs in the viewer, on a static site too. "Take in" makes annotations from a PDF's own: from another copy of the same paper, one marked in Preview say, matched by page, place and words so that taking it in twice adds nothing; or from the PDF being read, whose own annotations are then left off the page while an annotation stands for each. Deleting one of those deletes loom's record only, so the file's own annotation is drawn again and can be taken in again. A comment a PDF holds can be read by clicking it whether or not it is taken in. Nothing syncs with a file, because saving through Apple's PDFKit keeps no identifier on an annotation and rewrites the file's fonts and text layer; and Skim keeps its notes outside the PDF unless it is told to embed them, so they are exported from Skim first.

A mark records the hash of the PDF it was drawn on and the words under and around it, and a drawing its distance from the nearest of them, so a changed file is noticed: the mark stands where those words are found again, on its page or another, a drawing at the same distance from them, and one whose words are not found is detached, listed and not drawn (A3). A changed PDF has no kept copy, so a mark found again says where, and there is no earlier version to open. On a work whose TeX source the library holds, a mark's words are also found in the source, and an agent reads which file and where. Wherever an agent reads a mark, through `loom since`, `loom ai annotations` or `loom here`, it gets a crop of the page around it, made with `pdftocairo` into the build directory, as an image over MCP; TeX it reads off a crop is its own reading (P8).

A colour taken in from a PDF is drawn as the nearest of the nine, and a strike-out is struck. The exact colour stays on the record, and a saved copy writes it back unless the reader has since changed the mark's colour.

**Open.** How a note cites a script by path and hash, until loom can run code. A note in a format the viewer does not draw, org among them, shows as text, its links still counted, until a hook renders it ([WQ-70](../work-queue/WQ-70-note-renderer-hook.md)); `[[wikilinks]]` between Markdown notes are [WQ-71](../work-queue/WQ-71-wikilinks.md).

## Sessions and transcripts

A **session** is a stretch of work, which a person and agents may share, and its audit trail: `run.log` lists every loom command run in it, and its directory holds what an agent hands the author, such as a script a report cites; the report itself is a message in the session's transcript. An annotation belongs to no session: it carries its author, its time and the version it was written on.

Sessions are not what work is organised around. Work collects around the mathematics: annotations are found from what they are about.

A session's **transcript** is what its participants wrote deliberately with `loom session say`, not a copy of a conversation held in an agent app. An agent writes it so that someone coming back later sees the main points of the discussion, what was decided or found, what is still open, and links to everything durable that came of it. The viewer shows a transcript beside the documents it refers to, its links live, like a long-running annotation.

The viewer's chat composer and agent launching are retired (plan 0.20.1): conversations happen in agent apps, which own the model, the streaming, interruption and permissions.

## The viewer

The viewer shows what loom publishes and lets a person read and decide: read documents and works, follow links between them, see annotations and notes where they belong, review and accept. It writes nothing itself; every write goes through a control the publisher advertises, and only when the publisher serves it (P11). It works offline, from a static build, on any host.

The principles that govern it are the V and A sets. In short: open on the thing itself, show less, claim only what is known, and never lose the thing you followed a link from.

The frame is a left column and one or two panes. The column has four views, **Docs**, **Library**, **Web** and **Review**, whose names in the column, each with a hover card saying what the view is for, are the only controls that change view; what each view is for is `library.md`'s ("The views") and what each draws is `docs/specs/library-views.md`'s, and what follows adds what that spec leaves out. **Docs** holds the project's tree under **Files**, a shelf open by default and folding, a rounded box holding its head and its rows, so that Files reads as the quilt's directory as it is (its directories and the files the viewer shows, each directory folding as an explorer's does, at the reader's click alone, so a folded folder that holds the file being read stays folded, its name in bold and its hover naming that file; a document opens as itself, each agent copy beneath it, hung from it by an arrow pointing up into its name, and the tree says nothing of its compile, its PDF opening from its toolbar; the research state opens as its page where it lives, an included `.tex` file opens the document that reads it at its place, and every other file opens as a file; LaTeX's auxiliary files, such as `.aux`, `.log` and `.synctex.gz`, are left out unless the reader turns that off in Settings, and the agents' config documents, such as `AGENTS.md` and `CLAUDE.md`, when the reader turns that on; each row is marked "AI" where agents may edit it too and "AI" struck through where only the person does, its meaning shown under the pointer, and only Settings changes which), an agent copy whose document is not listed under Agent documents, with the closed ones folded beneath, Open a work…, Notes once a file of the quilt links into it, and the focused document's Outline (search is ⌘K). A draft whose last compile after a change made no PDF, or made one with errors, says so over the draft, with why (in the person's words where the viewer knows TeX's message) and the line TeX stopped at. **Review** lists what waits for the person's decision by kind, with the drafts that narrow it and Agents still working apart beneath them; at its column's foot, History holds what has been done, on tabs: Versions, each document's, one kept at every act, to open, compare with now or restore; Sessions, every one, with when it was last active, each opening its transcript, to rename, close, reopen or delete; and Everything recorded, each act the history holds. An agent's copy opens from Proposed edits on a page of its own in Review, where it is taken in. Problems is a page of its own in Review, which its column lists among the kinds by its name, with its count: the problems in the person's own LaTeX, a document whose last compile failed or finished with errors among them, a document that is gone with annotations on it, a link in one of their Markdown files to a file, a key or a place in one that is not there, and a write loom could neither finish nor undo, offered Settle as it stands (`writes.md`), which the manifest marks by class: what is wrong in the person's files first, the only part counted, then, folded, what is wrong in the LaTeX of an agent's copy; loom's model of the quilt and its own difficulties are an agent's, which `loom lint` lists with every code, and no fix is shown as a command. A viewer served none of Review's reads, as on a static build, shows Review as four sections instead, Your Changes, Proposed Changes, Problems and History, each counting what waits there and opening on the first where something does. The column's edge drags sideways to widen or narrow it, as the line above the Outline drags up and down, each remembered in the browser. In every view, its foot carries, from a write's answer, which comes once loom has recorded the write, until the page carries it, a line saying the page is updating (said instead when the build that was to show it failed), the column's message, saying what was just done with `undo` where it can be taken back, the legend of the marks, and the connection chip, which says whether an agent is connected and opens what it is told, sees and may change. Nothing in the viewer chooses a session: a session is an agent's report, read from Review › History. Ask your agent, at a selection and on an item's toolbar, opens a box that copies a request naming the place, in one of the quilt's modes if the person picks one, for them to paste into their agent's conversation; it writes nothing and starts no agent. Each pane has its tabs and, beneath them, its own toolbar: the item's views, its tools, a document's `history ▾`, and `view ▾` (which can hide every annotation in that pane). A document's `view ▾` holds `view PDF` (a version's does not), which opens its compiled PDF beside it, as a link in a pane opens, and says beside it how its compile stands, or `not compiled yet` where none was ever made; it is greyed only where there is no PDF to open, so a PDF kept from before a failed compile, or one compiled with errors, still opens. A compiled PDF's `view ▾` holds `open in browser`, the file at its own address in a new tab for the browser's own viewer, and `save as…`, which hands the file to the browser's download under its document's name; a project's own PDF has `open in browser` there too, and a cited work's `open the PDF`. A draft's history lists its live text and the versions that kept its text, newest first, each by the act it was kept at, the newest twelve and then, on asking, the rest in the same menu, and records a version of the draft by name in place; a version is shown read-only in the draft's own tab, its toolbar stepping to the older and newer ones and putting the document back as it, and each version, and each agent copy of the draft, can be compared with the one shown, which is how compare starts; while comparing, the focused pane's toolbar counts the differences and stops. `/` opens reading where it was left, remembered per quilt in the browser, else the front door, else the default document; a quilt with nothing to read opens on how to start, drawn from the publisher's `loom:no-live-document` fixes.

**Open.** Where a person meets a problem in their LaTeX. What is built in Docs is the line over a draft that did not compile or compiled with errors; everything else is on Review's Problems page, which Review's column lists among the kinds, and nothing in Docs links there. How the rest might reach the person on their document, a mark on it in the tree and in its toolbar with its problems gathered on one page reached from the document, say, is a change of layout to decide.

A file item shows any file the viewer shows by its kind: a Markdown file or a notebook drawn by the publisher (a notebook from its saved cells; loom runs nothing), where the HTML a Markdown file holds is drawn too, a video embedded from another site among it, through an allowlist that lets nothing in it run as the viewer ([dialect](../specs/dialect.md#1-envelope)), an HTML page in a frame of its own origin, where its scripts and embedded players run and from which it can never reach the viewer, a PDF and an image as they are (a PDF with its marks, and pages to edit: turned, deleted, reordered and inserted from another PDF, always into a new file, P7), text as text. A Markdown file's page is read as a document's text is: its annotations are drawn on their words and open their popups, its pending changes, an agent's suggested edits among them, are marked in its margin with Keep and Discard, words selected on it are offered Quote, Ask your agent, Annotate and New note and its toolbar holds the annotating tools, all on the file by its path. A task item in a Markdown file, `- [ ]`, is drawn with a box the person ticks in place, which writes that one character to the file, keeping its old text and recording the tick in the history (P7); a notebook's boxes are only drawn. An HTML file may read the project's shown files, list them at `/.loom/files.json` and open anything through `quilt:` links, so a quilt can build its own list or tracker; it cannot write, and its browser storage lasts only until `loom serve` restarts (`specs/write-api.md` §3). Anything else is named, with "Open in its application" for a document type (a spreadsheet, an Anki deck), which `loom serve` opens on the person's click and never for a file that runs code; an `app:NAME` link opens an application the same way. What the viewer shows is what a link may name, by the file's path, at a heading, a page, a text file's line or an anchor; a link in a Markdown file that names nothing, or a place its target lacks, is reported by `loom lint` on the line that wrote it, judged as the page reaches it. Only LaTeX is understood (ids, closure, states, acceptance).

A PDF opens where the person last was in it, a work's paper and a project's file alike, kept in this browser as the page at the top of the view and how far down that page, so it holds at another zoom or width. A link that names a place goes there instead, and where it lands is then where they are; once they have scrolled that page out of view by hand, the place comes off the address, so a reload stays with them. The place belongs to the file, known by its own identifier and page count: the same bytes opened as a work's paper and from Files are one place, and a different file behind a work opens at its start, since its page 12 is not the page they were on.

Settings is a window over the page with two groups of sections, each page saying where its settings are kept. **Loom** holds Profile (your name, in your user config, for every quilt), Appearance (how text looks and a document reads) and Files (what Docs shows of the project), the last two kept in this browser. **Quilt** holds the quilt's `config.toml`: its name, id prefix and engine, its front door and default document, where agents may not write and whether their edits in place are reviewed, the library's use of the network, and the Overleaf mirror: paired from the project's link, with a git token asked for once and kept in the Mac's Keychain, the folder it goes in, its main file and which of its authors is the person, then updated by Update from Overleaf, there or on a mirrored document's toolbar, beside a line saying what the last update brought and whose changes Review lists. Quilt also holds Lean, kept on this computer for this quilt and never in it: the person's switch that turns formalization on here, under which the install's steps and how it ended are said, and Check again, which has loom check the Lean, as the Web also offers beside a result's Lean. This browser's settings apply at once. The quilt's wait for Save, since the file is committed and shared, and are written line by line, so the person's comments and order stay; each shows its key. The history folder and the research state's path are shown and never changed there, since moving either means moving files with it. Saving the quilt's settings and rewriting Claude Code's permission file to a changed deny list are the author's acts. A viewer with no publisher shows the quilt's settings as published, and a command the viewer cannot run for the person reaches it from the publisher, never in its own words.

**Annotating** happens on the document itself. The pane's toolbar has two rows: the first holds what reads (the views, Changes, the stepper, Comments and Notes, a PDF's page and zoom, history and view) and **Annotate**, which shows or puts away the second, the annotation row, which holds the tools that write; the row is shown at first, kept in the browser once put away, and putting it away puts down any tool in hand, while showing it arms none. This is the interim layout until the toolbar's workshop (WQ-68). The annotation row holds the highlighter, which stays on until it is turned off and marks the words selected in the look in hand, widening a drag that stops partway through a word to the whole word, and Comment, which leaves a comment at a place; beside them, the format menu holds Plain and the quilt's types, numbered, the look (nine colours, underline, highlight or strike, a thickness in whole pixels, an opacity), Save as new type, and Customize, which opens Settings › Annotations. Plain keeps its own look, whatever type was held between. A look that differs from its type's, or from the plain look, says so, with Reset and Update. Words marked Plain, or with a type that only informs, are written at once, and typing then starts their comment; a type that stays open asks for its comment first, in a draft that says it is not saved, keeps its own type, and asks before Escape throws its words away. No single key hides annotations: a letter typed in the wrong place must never make what a reader is looking at disappear. The toolbar also holds Undo and Redo over the person's own annotation writes, a stepper through the annotations in reading order (J and K), and Comments, counting the annotations here, and Notes, counting the files that link here, and a line beneath it says what the tool in hand does, or what a draft still needs. An annotation has one margin icon, and a line where several start shows their count, which opens a chooser. Every annotation opens one popup: its type and look, its comment, edited in place, its replies, Resolve where its type stays open, and Delete. One whose words have changed since it was written says so with its words as they were, opens the version it was written on with that version's annotations drawn, and keeps a mark where its words were. Comments lists every annotation in reading order, with To do (the open annotations of others) and a filter by person and for resolved ones; Notes lists the files of the quilt that link here, each with the words its links quote, opening the note at its link (see Notes). Selecting words offers their actions at a click (see Notes). Settings › Annotations shows Plain and one type at a time and writes the types file. A running `loom serve` keeps the code it started with and the viewer it started with, and a page says when loom has been updated since, and to restart it.

Things are shown where they live (V7): a statement in a document that holds it, a cited result on its work's page, an annotation on the words it marks. A result included in several documents opens in the one the link stands in, else one on screen, else the one looked at last; a result in no document, or a work with no PDF, is the one case for a view of its own, and a project file is shown as itself.

Resting on a link shows a card of what it names, a glance and not a home (V7). A link to a document at a place, `quilt:DOC#rl-0004` as an agent writes one, shows what is at the place, the card a link to `rl-0004` shows, while a click still opens the document there; a link to a document alone, or at a place the manifest does not know, shows none. A reference to a labelled equation, a `\ref` or `\eqref` in the text or a `quilt:` link to `rl-0004#eq:main`, shows that display alone, typeset with its number as the page of the result or section it stands in shows it, under a head naming its number and what it stands in (`(3) in proof of Lemma 1.2`); where that page's text holds no such display, the card is the result's or the section's own.

## Coauthors

Coauthors clone the quilt. Sources, the records, the library and the agents' sessions and copies are shared; `.loom/.gitignore` names what is not, by folder (`local/`, `cache/` and `agents/scratch/`), personal settings stay in the user config, and identity is never stored in the quilt. Acceptance is per reviewer. Two coauthors who allocate the same node id on separate branches get a conflicted key after the merge, which `loom fork` resolves. A person who writes on Overleaf pairs the quilt with the project once: loom clones it over git into `.loom/local/overleaf/`, which is this machine's, and copies its files into a new folder of the person's, which only an update writes (`loom/src/loom/overleaf.py`). An update takes Overleaf's bytes into that folder on the person's word, stamping each document it reaches first (P7), and loom never writes back to Overleaf. Who the person is on Overleaf is this machine's too, so each coauthor sharing the quilt says it once.

An annotation's id, like a suggested edit's and a session's, ends in a token drawn at random rather than a count (`a-2026-11-05-k2m9xq`, `e-2026-11-05-q4hd2r`), so coauthors writing on the same day draw different ids. The token says nothing of order, so a listing takes its order from when a record was written. These records live in append-only logs, except that deleting an annotation rewrites the annotation log, and git calls two clones' additions to one a conflict, which keeping both sides resolves. Should two records still reach a log under one id, by a line such a merge kept twice or a draw that came up the same, `loom lint` reports `loom:repeated-id`, naming the lines and the edit that clears it, and loom changes neither record (P13).

**Open.** A step's number and a message's number are still counted, because each is an order as well as a name, and a random token would lose that. Two clones that each make a step leave a merged ledger reported as `loom:history-corrupt`, which reads without the later step and has no command that mends it. Two clones that each write in one session leave two messages under one number, which nothing reports: `loom:repeated-id` does not read transcripts, and the viewer, which holds a transcript by number, shows only one of them.
